传统测试 · 可靠性

规则、经验、领域判断和责任边界，守住核心流程、验收口径、风险优先级和发布底线。

AI 测试 · 放大器

理解、生成、归纳和探索，快速扫描代码与需求，扩展场景组合，减少机械劳动和信息遗漏。

人机协同 · 闭环

人定义质量，AI 扩展覆盖，程序验证事实：模型不确定就留痕，执行结果反哺规则和回归资产。

系统定位：让 AI 处理“规模与变化”，让测试工程师守住“语义与责任”，再用工程化门禁把两者连接成稳定交付。
AI 不替代测试判断，而是把判断变成更大规模的质量证据LLM-AutoTest · 2026

02 · ARCHITECTURE
Evidence-driven pipeline

一条流水线，三道护栏

模型输出不是最终事实。每个语义节点都经过结构化契约、代码回填和执行反馈，最终才进入报告与回归资产。

输入与证据 · Inputs / Evidence
需求文档原文、基线、差异与澄清项
代码仓库版本、分支、源码与运行配置
被测环境接口地址、鉴权、前端入口
编排与 LLM 节点 · Orchestrator / LLM-assisted Nodes
01 需求解析需求项 / 风险 / 测试点
02 源码扫描代码证据 / 变更范围
03 接口还原协议 / 参数 / 响应
04 Code Review映射 / 缺口 / 风险
05 用例生成normal · boundary · exception
06 E2E（可选）页面、动作、断言
07 自动执行接口 / 浏览器真实运行
08 报告与缺陷预期、实际、证据分流
09 回归沉淀稳定通过项进入资产库
三道护栏：Schema 结构门禁 → 代码事实回填 → 真实执行与复测；模型不合规时定向修复，无法证明时保留人工介入。
输出与质量资产 · Outputs / Quality Assets
可追溯用例需求、接口、测试点与脚本关联
缺陷证据接口、用例、期望、实际与复现路径
回归资产通过门槛、版本与复测历史
语义生成输入 / 可选分支可交付质量资产
固定编排 · 分批生成 · 可恢复执行 · 全程留痕LLM-AutoTest · 2026
