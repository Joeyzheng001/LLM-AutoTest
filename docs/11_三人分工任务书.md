# 五、泳道间依赖与接口约束（统一战线的「作战地图」）

> 本章把三个人之间的全部依赖摊开：谁欠谁什么、什么时候给、给的质量标准、单方面变更的后果。**每条约束都是双向的——提供方的义务 = 消费方的权利。**

## 5.1 依赖全景图

```
                    【D1 关键路径·最硬】
  乙 ═══════════► 接口候选清单 ═══════════► 甲（LLM 语义解析）
  │                                            │
  │ 【D4 弱】兜底仓库埋入缺陷说明              │ 【D2 硬】interfaces.json
  ▼                                            ▼
  丙（写预期失败用例）                    丙（用例生成的输入）
                                               │
                  【D3 硬·Day 3 冻结】          │
  甲 ═══════════► orchestrator REST API ═════► 丙（4 个前端页面）
                                               │
  丙 ─────► execution.json 结构（Day 1 冻结）────► 甲（编排第 7 节点触发报告）
```

**结论**：业务本质存在串行链（乙 → 甲 → 丙），分工无法消除它，只能靠「契约先行 + 假数据并行」把等待推迟到 Day 4 联调日。这是刻意设计，不是缺陷。

## 5.2 逐条依赖约束（义务 × 权利）

### D1 · 乙 → 甲：接口候选清单（关键路径，优先级最高）

| 项 | 约定 |
|----|------|
| **甲有权要求** | ① Day 2 中午前收到 ≥5 个真实候选的**样例文件**（结构完整、可喂给假数据流程验证）；② 每个候选必含：协议类型、签名、代码位置（仓库+文件+行号）、源码片段、关联文件链、is_fallback 标记 |
| **乙的义务** | ① 样例不迟到——迟到即阻塞关键路径，站会当场上报；② 候选结构严格符合 `schemas/contracts/` 冻结版，字段不达标甲有权拒收 |
| **甲的义务** | ① Day 1–3 用假候选完成全部解析逻辑与单测，**不得以「等乙的真数据」为由暂停**；② 发现候选质量差（解析错漏）时反馈给乙并保留记录，不得自行修正静默吞掉（诚实口径） |
| **违约后果** | 乙的样例迟到半天以上 → 启动 R1 应对：甲先用兜底仓库（乙 Day 3 才交付）的候选顶上，真实仓库结果在报告中如实分列降级说明 |

### D2 · 甲 → 丙：interfaces.json（用例生成的唯一输入源）

| 项 | 约定 |
|----|------|
| **丙有权要求** | ① Day 1 下午 Schema 冻结时拿到 `interfaces.json` 的结构定义 + **一份假数据样例**（≥3 个接口、覆盖至少 2 种协议）；② Day 4 上午拿到真实产物 |
| **甲的义务** | ① 假数据样例由甲提供（不是丙自己瞎造——保证结构语义和真实产物一致，避免 Day 4 联调对不上）；② Schema 变更只许加可选字段，删改须丙会签 |
| **丙的义务** | ① 生成器参数校验以 Schema 为准（出现接口清单外的参数即打回，F-GEN-02）；② 不等甲的真数据，Day 1 起用甲给的假样例开发 |
| **违约后果** | 甲的假样例缺失或与最终真实结构不一致 → 联调返工时间计入甲的泳道（排期风险显式归责，不许摊给丙） |

### D3 · 甲 → 丙：orchestrator REST API（前端 4 页的数据源）

| 项 | 约定 |
|----|------|
| **丙有权要求** | ① Day 3 上午 API 契约冻结（三视图【含人工审核回流端点】/报告/缺陷/度量四组端点的请求响应结构）；② 同步拿到一份各端点的 **Mock 响应文件**（丙写页面用） |
| **甲的义务** | ① 契约含错误结构 `{code, message, node_id?, details}`（三栈统一）；② API 数值端点（自动化率、通过率）返回**程序化汇总值**，不得让前端算数 |
| **丙的义务** | ① 页面先用 Mock 响应开发，Day 4 换真 API；② 页面不吞错误、不合并兜底/真实数据（展示红线） |
| **违约后果** | API 契约 Day 3 未冻结 → 丙的 4 页顺延不算丙的延误（归责甲），丙转而先完善六页骨架与 Mock 数据 |

### D4 · 乙 → 丙：兜底仓库埋入缺陷说明（弱依赖，非关键路径）

| 项 | 约定 |
|----|------|
| **丙有权要求** | Day 3 前收到埋入缺陷清单（哪个接口、哪个分支、预期错误行为） |
| **乙的义务** | 缺陷埋在业务逻辑层 + 独立分支 + 不进主干；说明含「预期失败用例怎么写」的对照信息 |
| **丙的义务** | 演示脚本里的预期失败用例按说明写，且演示缺陷来源显式标注「独立分支埋入」（不冒充真实发现） |
| **违约后果** | 迟到不阻塞丙主线（丙先用 Mock 服务模拟失败场景），但演示物料完成时间受影响时归责乙 |

### D5 · 丙 → 甲：execution.json 结构（反向弱依赖）

| 项 | 约定 |

## 5.4 横切数据约定（三人 Schema 的「公共语言」，Day 1 随 Schema 一并冻结）

> 这些字段出现在多个人的 Schema 里，格式不统一 = Day 4 联调对不上 = 最大返工源。**由「生成方」定格式，引用方不得自造。**

| # | 约定 | 规则 |
|---|------|------|
| 1 | ID 命名 | 需求条目 `REQ-001`；接口候选 `CAND-001`；接口 `IF-<协议大写>-001`（如 `IF-REST-001`）；用例 `TC-001`；缺陷 `DEF-001`；任务 `job-<UUID>`。序号三位零填充，跨仓库全局递增 |
| 2 | 时间戳 | 一律 UTC、ISO-8601 字符串（如 `2026-09-15T08:30:00Z`），禁止本地时区（R-DEF-03 审计口径） |
| 3 | 协议枚举 | 统一小写字符串：`rest` / `grpc` / `graphql` / `soap` / `mq`（与 java-parser 契约一致，禁止 `REST`、`Rest` 等变体） |
| 4 | 版本字段 | 每个产物根节点含 `schema_version`，两位简化语义化（从 `1.0` 起） |
| 5 | 兕底标记 | `is_fallback` 从仓库输入一路透传到 defects / metrics，任何中间产物不得丢弃（D5 分列的数据基础） |
| 6 | 错误结构 | 跨服务统一 `{code, message, node_id?, details}`（契约已定，Schema 沿用） |
