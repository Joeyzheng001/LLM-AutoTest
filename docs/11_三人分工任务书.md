## 一、分工总则（独立开发机制）

1. **三条泳道，域内闭环**：每人拥有独立服务/模块域，从代码、Schema 到测试全栈负责，日常开发互不等待；
2. **契约先行，假数据并行**：全部跨人依赖（产物 Schema、REST API、Prompt 接口）在冻结时点前定义完毕（见「六」），冻结后各泳道以假数据开发，联调集中在里程碑日；
3. **门禁即合入标准**：CI 绿灯（ruff/mypy/checkstyle/eslint/单测，[09](09_开发规范说明.md) 第十章）+ 1 人 cross-review；红线（[.rules/llm-integrity.md](../.rules/llm-integrity.md)）违反即驳回；
4. **页面跟 API 走**：前端页面按后端提供方分配（P1 页面对接 orchestrator，P3 页面对接下游模块），避免跨人接口联调。

## 八、协作机制

1. **每日站会**（15 分钟，R6 应对）：同步冻结物变更与阻塞；
2. **cross-review**：合入门禁 1 人 review，跨泳道变更（schemas/、contracts/、.rules/）须相关方会签；
3. **分支约定**：`feat/<泳道>/<任务号>`（如 `feat/p3/07-exec-runner`），存活 ≤1 天（docs/09 九）；
4. **阻塞上报**：任一泳道里程碑延误 >半天，站会即时启动 R1 应对（优先级重排，不裁功能）。

## 九、负载与风险说明（诚实记录）

3. **本任务书不改冻结基线**：人力 4→3 的口径调整建议按 06 变更控制规则第 3 条在冻结文档补记（负责人确认后执行），本任务书作为实施依据先行生效。
