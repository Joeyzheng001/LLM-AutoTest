# 需求差异分析：product_requirements v1.0 → v1.1

> 对比对象：v1.0（2026-09-15，458 内容行）→ v1.1（2026-09-16，655 内容行）
> 说明：`product_requirements.docx` 与 `product_requirements 2.docx` 为同一文件（MD5 一致），本报告实际对比的是 v1.1 与流水线此前使用的 v1.0 旧版。
> 规模：净增约 200 行规格内容；业务域从 4 大扩至 5 大（新增 TA 清算），核心功能点 15+ → 20+。

---

## 一、新增功能模块（P0/P1）

### 1. TA 清算确认（FS-EP2-6，全新模块，P0，待实现）★ 最重大变更
- 待确认交易列表（状态为 P 的交易）、单笔/批量确认（统一成功或失败）
- 确认计算：确认份额 = 确认金额 / 基金净值（净值来自产品配置）；失败则份额/金额置 0
- 状态流转：P→C（确认成功）/ P→F（确认失败）；可确认任意历史日期
- 双表更新：order_record + settlement_record 同时更新
- 异常口径：空选阻止、并发状态变更拒绝、净值未配置拒绝
- **新增 API**：
  - `GET /api/clearing/pending/?page=&work_date=`
  - `POST /api/clearing/confirm/`（`{serial_nos[], action: "confirm"/"reject"}`）

### 2. 账户信息查询（FS-EP3-1，全新 P0）
- 客户名称模糊匹配（icontains）+ 证件号码精确匹配；至少一个条件，禁止无条件查询
- 分页每页 20 条；生产环境建议证件号/手机号脱敏
- **新增 API**：`GET /api/accounts/query/`

### 3. 八个交易/账户子功能详细规格（v1.0 仅列清单，v1.1 补全规格）
| 功能 | 编号 | 关键业务规则 |
|---|---|---|
| 赎回下单 | FS-EP2-2 | business_code=24；录份额（application_vol>0，金额=0）；仅 S 状态可赎回 |
| 快取下单 | FS-EP2-3 | business_code=98；按份额，规则同赎回 |
| 撤单 | FS-EP2-5 | business_code=CD（含冲正）；只能撤 P 状态；work_date ≥ 当前工作日；已确认为终态不可撤 |
| 机构开户 | FS-EP1-2 | investor_type=0；统一社会信用代码 18 位校验；法人/经办人必填 |

| 修改客户资料 | FS-EP1-6 | 全字段可改、覆盖更新、保留修改历史 |

## 二、新增全局口径（v1.0 无对应章节）

**4.0 全局系统常量**：tano=47（管理人）、distributorcode=247、branchcode=247、currencytype=156（人民币）、takeincomeflag=0——均后端固定填充、前端不展示。

**交易状态码**（替换 v1.0 的 pending/submitted 两态口径）：
- D 已提交 → P 待确认 → R 处理中 → C 已确认 / F 已失败；D → P → X 已撤单；C 为终态不可撤单

**产品状态码**（全新）：N 认购期（仅申购）/ S 开放申购期（全部交易）/ P 暂停 / F 发行失败 / L 已清盘 / C 封闭期（后四者禁止交易）。

**系统页面结构**：明确 7 大模块（首页/账户/交易/查询导出/TA 清算/对账/产品配置）。

## 三、既有功能业务规则变更

### 产品配置（FS-EP0-2）
- 表单新增：**产品状态**（N/S/P/F/L/C）与**当前净值 NAV** 字段
- BR4 收紧：交易下拉框仅展示 `is_active=true` **且产品状态为 N 或 S** 的基金（v1.0 只看 is_active）
- 新增 BR5 产品状态限制交易、BR6 净值用于 TA 清算份额计算、BR7 启用/停用独立于产品状态

### 申购下单（FS-EP2-1）
- 交易状态口径：~~pending→submitted~~ → D(已提交)，TA 清算确认后 → C/F
- 金额新增显式上下限：0.01 ~ 99999999999999.99
- 新增 BR7 基金状态限制（N/S 才可申购）、BR8 确认份额计算

### 基金转换（FS-EP2-4）
- business_code：~~36~~ → **036**
- 新增 BR4（转出/转入基金状态均须 N 或 S）、BR5（确认份额计算）、BR6（同基金公司，无需公司字段）

### 对账执行（FS-EP4-1）★ 匹配口径重大变更
- 匹配规则：~~流水号+金额+份额+时间+账号 5 字段匹配，金额/份额容差 ±0.01~~ → **按流水号（ec_ap_serial_no）单一主键匹配**
- 差异类型：~~金额不一致/份额不一致/缺失下单/缺失落库~~ → 金额不一致/份额不一致/**状态不一致**/**单边账**（缺失下单/缺失落库归并为单边账，新增状态不一致）
- 新增：对账日期可选任意工作日；结果导出 Excel + CSV
- ~~容差（Tolerance）概念删除~~

### 交易记录查询（FS-EP3-2）
- 查询条件扩充：新增**基金代码**、**交易类型**组合查询；日期限定只能选工作日

### 幂等性（安全性/一致性章节）
- 口径变化：~~同一流水号不可重复提交（唯一约束拒绝）~~ → 重复提交**返回上次结果**而非创建新记录
- 新增：后端输入 XSS 过滤、SQL 注入防护、特殊字符过滤

### 个人开户（FS-EP1-1）
- 自动生成字段新增：ec_financeno（基金账号，64 位）、ta_account_id（47 开头 12 位）
- tano=47 后端固定填充；销售商/网点代码从「可选」改为「后端自动填充 247，前端不展示」
- 新增 BR6~BR9（含同一证件号唯一约束）

## 七、对自动化测试的影响（LLM-AutoTest 流水线视角）

1. **用例设计影响最大**：TA 清算（P0 全新）、账户查询（P0 全新）、状态机校验（D/P/R/C/F/X 流转断言）、产品状态×交易类型组合矩阵（N/S/P/F/L/C × 申购/赎回/快取/转换）是 v1.1 的增量测试点
2. **对账断言口径变化**：差异类型从 4 类变 4 类但语义不同（新增状态不一致、单边账合并），v1.0 口径生成的对账用例预期需重审
3. **幂等性断言变化**：从「重复提交被拒」变为「重复提交返回上次结果」——正向/异常用例的预期结果相反
4. **转换业务码**：36 → 036（三位对齐，涉及校验正则）
5. 此前 e2e 提交的 job 使用的是 v1.0 文档；如需覆盖 v1.1 新增功能点，需用 v1.1 文档重新提交 job
