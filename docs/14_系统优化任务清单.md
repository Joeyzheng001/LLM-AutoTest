## 已完成：P0-01

### 目标

明确哪些信息进入数据库、哪些继续保留为 JSON/文件产物，并设计不破坏现有 job 的迁移路径。

### 交付物

- 数据模型草案：jobs、job_nodes、job_events、artifacts、job_configs、repo_snapshots、credentials；
- JSON 产物与数据库状态的权威边界；
- 现有 `/tmp/llm-autotest` 任务目录迁移规则；
- 服务重启、历史任务读取和导出兼容规则；
- P0-02 Worker 需要使用的状态和锁字段。

### 验收标准

- 不删除现有 JSON 产物，不改变已有产物 Schema；
- 历史 job 能被识别、查询和导出；
- 数据库故障时不会静默篡改产物；
- 明确区分任务状态、节点状态、事件日志和产物版本；
- 迁移方案可支持后续多进程 Worker。

### 本次实现与验证

- 新增可选 SQLAlchemy 持久化基础层：`jobs`、`job_nodes`、`job_events`、`artifacts`、`job_configs`、`repo_snapshots`；
- 新增 `DATABASE_URL` 配置入口；未配置时继续使用现有文件型流程；
- 产物只登记路径、版本、校验和、大小和 Schema 校验结果，不把大文件正文塞进数据库；
- SQLite 专门测试、Ruff、mypy 和后端全量测试均通过：`227 passed, 2 warnings`；
- 依赖数据库的双写、租约领取和多 Worker 运行留到 P0-02/P0-03，避免一次切换影响现有任务。

  存储、备份恢复和密钥不出日志等部门部署验收原则；该类运维规则不注入业务生成 Prompt。
- 数据库模式下提交/修改/重跑会保存脱敏的 `job_configs` 版本快照；本地 `job_input.json`
  不可见时可恢复非敏感运行参数，并按对象存储还原需求文档到当前实例路径。
- 流水线 runtime 事件同步登记 `job_events`；日志接口在 JSONL 不可见时补读数据库，并对
  文件/数据库重复事件去重，保持当前与历史轮次展示口径。
- 多实例队列未获得数据库租约时立即跳过，不会在租约释放后重复领取同一任务；显式重跑仍
  通过原有 API 在旧任务结束后创建新的队列项。
- Runner 镜像节点状态时携带任务租约 Worker 身份；数据库拒绝租约已切换或已过期 Worker
  的回写，避免旧实例覆盖新实例页面状态；历史索引补录仍保留无身份兼容入口。
- 任务级心跳续租失败时主动取消旧 Worker 的执行协程，避免租约丢失后继续调用 LLM/被测
  服务或写入证据；新实例只执行自己成功领取的租约。
- 长期记忆继续使用版本、规格号、适用节点和变更记录；Prompt loader 留痕引用版本，缺失或
  元信息不合规时按 `X-LLM-03` 处理，不静默跳过。
- Skill/记忆准入回归要求映射文件具备版本、规格号、负责人、变更记录和非空正文；同一节点
  禁止重复注入同一知识文件，避免经验失效或上下文膨胀。
- 任务执行协程结束后清理内存中的鉴权 Cookie、LLM 配置和 Git Token；鉴权预检会回收过期
  待验证会话，生产重跑由 SecretStore 恢复，不让敏感映射按任务数量无限增长。
- 用例生成长期规则已补齐：单对象仅在字段完整时无损提升为单元素 `cases`，批次按接口×三类
  场景做覆盖门禁；`recon_date/pk/close_type` 等跨节点字段和空对象不做猜测式兼容，修复轮
  仍失败即保留检查点并人工介入。
- 部门 Compose 已强制要求 `SECRETS_ENCRYPTION_KEY`，避免生产部署遗漏密钥后静默使用明文
  兼容模式；本地开发 `create_app` 仍可保留兼容行为，但不得作为部门部署验收依据。
- 部门 `.env.example` 已统一 MiniMax-M3；预检未填写任务级模型时只提示复用服务级 LLM 配置，
  不再把生产路径描述为桩执行。
- 服务级 `Settings` 缺省模型已同步为 MiniMax-M3，LLM 客户端与需求评审提示词不再遗留 GLM 默认口径；历史冻结文档/演示快照保留原始记录，不作为当前运行配置。
- 服务级 LLM 单次调用超时默认统一为 300 秒，并在 `.env.example` 显式展示；仅调整等待窗口，不放宽有限重试和 Schema/覆盖门禁。
- 部门 `.env.example` 不再携带 `change-me` 数据库密码或可直接使用的访问令牌示例，相关 required 变量必须由部署环境/密钥系统注入。
- `Settings` 增加启动前配置门禁，拒绝非法 LLM 地址/模型/超时、采样参数、队列并发/租约和保留期，避免错误配置进入后台运行态。
- 新增 `orchestrator validate-deployment` 部署预检 CLI，在数据库迁移和服务启动前校验 PostgreSQL、SecretStore、访问令牌、MiniMax 与 S3/MinIO 配置；不发起外部连接、不输出密钥。
- 部署辅助脚本不再保存任何服务器账号密码；如确需临时远程执行，只从环境变量读取目标和凭据，优先使用部门密钥系统或跳板机。
- 队列已回收成功、失败和取消任务的 `asyncio.Task` 引用；活动计数只基于当前任务，历史状态
  由数据库或产物状态查询，避免共享服务长期运行内存增长。
- API 运行态结果只保留最近 512 个，待消费鉴权会话最多 256 个并按 TTL/最旧优先淘汰；完整
  任务状态仍由数据库、`state.json` 和产物提供，避免异常流量造成进程内存无界增长。
- 部门 Compose 同时强制要求 `AUTOTEST_ACCESS_TOKENS_JSON`，共享部署没有访问令牌映射时不允许运行
  在匿名兼容模式；本地单用户模式仅保留给开发和单测。
- 浏览器仅持久化非敏感 LLM 参数；旧版本可能存在的 API Key 会在配置页加载时清理，已有任务继续由
  服务端 SecretStore 复用密钥。
- 新任务默认复用部门服务级 LLM 配置，页面仅在用户主动开启时发送任务级 MiniMax 覆盖参数；已有任务读取后保持原配置。
- 编辑已有任务时可明确关闭任务级 LLM 覆盖；服务端会清除旧任务级模型元数据和密钥，避免界面状态与实际运行配置不一致。
- 多实例入口已改为 Docker DNS 动态发现：Nginx 按请求解析 orchestrator，Prometheus 使用 DNS
  服务发现抓取全部实例；代理不自动重试 POST，避免任务提交和重跑重复入队。
- 内部 LLM 中转站已落地 `LLM_PROTOCOL`：可在服务级、任务级和重跑覆盖中选择
  `openai-chat`（Bearer + `/chat/completions`）、`openai-responses`（Bearer + `/responses`）或
  `anthropic-messages`（`x-api-key` + `/messages`）；调用留痕同时记录协议。Responses 与 Messages
  按各自响应体提取正文和原始 token，不以 Chat 响应结构猜测解析。
- 默认模型已改为内部中转站的 `deepseek-reasoner-code`；前端按已授权模型分组展示，但服务端保留
  自定义别名通道。图像生成类别只给出不适用于结构化文本流水线的提示，不伪造可用性。
- 任务配置页新增中转站连接测试：服务级/任务级均可测试，采用固定无业务提示、30 秒单次超时且无重试，
  返回协议、模型、耗时和原始 token；不创建 job、不保存模型正文或浏览器 API Key。
