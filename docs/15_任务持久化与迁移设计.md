# 任务持久化与迁移设计

## 1. 目标与边界

当前系统以任务目录和 JSON 文件驱动流水线：

- `state.json` 保存节点状态、错误和降级信息；
- `job_input.json` 保存任务输入和可复用配置；
- 九个节点产物以 JSON/Markdown 文件保存；
- `archive/` 保存重跑前的旧产物；
- `runtime_log.jsonl`、`llm_calls.jsonl`、`review_log.jsonl` 保存运行留痕。

部门共享部署后，目录扫描和进程内状态不能继续承担任务索引、并发锁和运行队列职责。本设计采用“数据库管理任务元数据，文件/对象存储保存证据产物”的过渡方案，不删除现有产物格式。

## 2. 权威边界

| 数据 | 生产环境权威来源 | 兼容期处理 |
|---|---|---|
| 任务身份、状态、创建/更新时间 | PostgreSQL `jobs` | 继续生成 `state.json` 兼容视图 |
| 节点状态、尝试次数、租约、错误 | PostgreSQL `job_nodes` | 与 `state.json.nodes` 双写；两侧可见时按节点 `updated_at` 合并，单侧可见时使用可见侧 |
| 状态变化和用户操作 | PostgreSQL `job_events` | 同步追加现有 JSONL 日志；runtime 事件在本地日志不可见时可回退读取 |
| 结构化产物内容 | 文件/对象存储 | 保留原文件名、Schema 和下载接口 |
| 产物版本、校验和、大小、地址 | PostgreSQL `artifacts` | 由 ArtifactStore 写入后登记 |
| 任务输入配置 | PostgreSQL `job_configs` | `job_input.json` 作为内部兼容快照；共享卷不可见时从最新脱敏快照恢复 |
| API Key、Git Token、鉴权密码 | Secret Manager 或加密字段 | 不进入 `job_input.json`、产物和 LLM 留痕 |
| Git 工作区 | Worker 临时目录 | 数据库只记录来源和 commit SHA |

数据库记录任务和状态，产物仍是可下载、可校验、可审计的证据文件。任何不符合 Schema 的产物都不能登记为有效版本。

## 3. PostgreSQL 最小模型

### 3.1 `jobs`

保存任务级信息：

- `job_id`：主键，沿用现有 `^job-` 规则；
- `status`：queued / running / completed / failed / stopped；
- `created_at`、`updated_at`、`started_at`、`finished_at`；
- `config_version`、`state_version`：乐观锁版本；
- `created_by`、`project_id`：为后续部门/项目隔离预留；
- `error_code`、`error_message`：任务级错误摘要。

### 3.2 `job_nodes`

主键为 `(job_id, node_name)`，保存：

- `status`、`attempts`；
- `started_at`、`finished_at`、`updated_at`；
- `worker_id`、`lease_expires_at`、`heartbeat_at`；
- `error_json`、`degraded_reason`；
- `version`：状态更新的乐观锁。

节点状态更新必须使用事务和版本条件，防止停止、重跑、Worker 回写互相覆盖。

### 3.3 `job_events`

追加写入，不原地修改：

- `event_id`；
- `job_id`、`node_name`；
- `event_type`：submitted / queued / started / progress / completed / failed / stopped / rerun；
- `payload_json`：仅保存脱敏信息；
- `created_at`、`created_by`。

前端运行日志和审计记录优先从事件流读取，不再通过扫描多个 JSONL 文件拼接。

### 3.4 `artifacts`

保存每个产物的可追溯信息：

- `job_id`、`filename`、`version`；
- `schema_version`、`sha256`、`size_bytes`；
- `storage_uri`、`created_at`、`archived_at`；
- `is_valid`、`validation_error_json`。

同一任务同一文件禁止无版本覆盖；重跑产生新版本，旧版本继续保留。

### 3.5 `job_configs`、`credentials`、`repo_snapshots`

- `job_configs`：保存脱敏任务配置版本，文档和仓库输入用引用关联；
- `credentials`：只保存 Secret Manager 引用或加密密文、用途、指纹和更新时间；
- `repo_snapshots`：保存仓库来源、本地工作区、target SHA、baseline SHA、拉取时间和缓存命中信息。

任何 Token、密码和 API Key 不进入普通配置 JSON、事件 payload、错误信息或 LLM 请求留痕。

## 4. 兼容与迁移方案

### 阶段 A：建表与只读导入

1. 创建 PostgreSQL Schema 和索引；
2. 扫描 `ARTIFACTS_ROOT` 下的任务目录；
3. 从 `state.json` 导入任务与节点状态；
4. 从产物文件计算 SHA-256、大小和 Schema 有效性；
5. 从 `job_input.json` 导入脱敏配置；
6. 损坏或无法识别的目录进入迁移报告，不删除、不覆盖。

### 阶段 B：双写

1. 新建任务时先写数据库，再创建任务目录；
2. 节点状态更新写数据库，同时生成兼容 `state.json`；
3. ArtifactStore 写入成功后登记 `artifacts`；
4. 事件同时写入 `job_events` 和现有 JSONL；
5. 旧任务仍允许从文件回退读取。

### 阶段 C：数据库优先读取

1. 任务列表、状态和运行锁优先读取数据库；日志仍合并文件/事件来源，保留历史文件兼容；
2. 产物详情按数据库索引定位文件或对象存储；
3. `state.json` 只作为导出和旧 CLI 兼容视图；
4. 数据库状态与产物不一致时进入对账流程，不静默修正。

### 阶段 D：多 Worker 运行

1. Worker 通过租约领取 `queued` 或超时回收的节点；
2. 心跳续租，租约过期后允许其他 Worker 接管；
3. 同一 job/node 使用数据库锁避免重复执行；
4. 停止、重跑和人工回流都通过事件和事务完成。

## 5. 索引与性能基线

- `jobs(updated_at desc)`：任务列表；
- `job_nodes(job_id, status)`：任务详情和恢复；
- `job_events(job_id, created_at)`：运行日志；
- `artifacts(job_id, filename, version desc)`：产物查询；
- `repo_snapshots(source_url_hash, target_sha, baseline_sha)`：Git 缓存命中。

大文档、代码压缩包和大体积产物不直接存 PostgreSQL，使用文件卷或 MinIO/S3；数据库只保存地址、校验和及权限信息。

## 6. P0-01 验收标准

- 不修改现有 JSON Schema 和下载接口；
- 历史任务可以导入、查询、打开和导出；
- 服务重启不丢任务、节点状态和运行日志索引；
- 数据库和产物不一致时有明确告警，不静默覆盖；
- 设计支持后续独立 Worker、并发锁和多实例部署；
- 敏感凭据没有明文进入任务产物、日志或 LLM 留痕。

## 7. 当前代码落地状态（2026-09-21）

- `services/orchestrator/src/orchestrator/persistence.py` 已提供 SQLAlchemy 模型、事务门面、产物登记和节点租约 API；
- 数据库引擎启用 `pool_pre_ping` 与 `pool_recycle=1800`，共享部署中优先发现失效连接并定期轮换；
- `DATABASE_URL` 为空时不创建数据库连接，现有文件型流程保持不变；配置为 PostgreSQL 后由显式 `migrate-db` 负责建表并登记 `schema_migrations` 的 `001_initial` 基线，`init-db` 仅保留兼容别名，避免服务启动时静默改生产结构；
- `LocalJobQueue` 已把 HTTP 提交与执行解耦，并限制单进程并发；配置数据库后，Worker 会先领取任务级租约，执行期间续租，结束后释放；租约续租失败时主动取消旧执行，避免旧实例继续写入产物；
- 服务启动时会查询 queued/租约过期 running 任务并重新入队；`state.json` 的 running 节点先回退为 pending，避免进程死亡后的假完成；
- 已有 job 的普通重复提交被拒绝，重跑使用专用入口并继续执行级联归档；停止、恢复和租约释放保持任务目录可审计；
- 当前已实现产物/任务归属/节点租约/节点状态/配置快照/runtime 事件的数据库双写、历史产物索引迁移、对象存储镜像与缺失恢复；任务列表和详情已数据库优先并保留文件回退，配置缺失时可从 `job_configs` 恢复，运行日志合并 JSONL 与数据库事件并去重；Runner 的节点快照回写带任务租约 Worker 校验，旧实例不能覆盖新实例状态；P2-03 剩余目标服务器双实例、备份恢复和 RPO/RTO 实演。
