## 关于 R4（为何不编号、是否归档、是否保留）

这里的 **R4** 表示工作坊/课程里的 **「第 4 轮展开」**（设计层多文档对齐），**不是** `04-PRD` 的「4」。它是一份**横向检查表**：在 `06/07/08/09/10/11` 都已有初稿后，按行核对「架构 ↔ 数据」「FSD ↔ NFR 错误码」「安全 ↔ API」等，避免从多个模块复制粘贴后出现口径打架。

| 问题 | 建议 |
|------|------|
| **为何要单独成文件？** | 不塞进 `13`/`14` 是为了**复用一张表**、打印/评审时只带一页；内容本质是**过程质量工具**，不是对外契约真源。 |
| **能否挪到 `归档/`？** | **可以**，但若团队仍在用 R4 做课中/PR 自检，放归档容易被当成「历史资料」而没人更新。**更稳妥**：保留在根目录；仅当明确停用该表时，再迁入 `归档/操作与实验说明/` 并在此处改链接。 |
| **是否要保留？** | **建议保留**（根目录或并入下文「附录」二选一）。对「多模块拼出来的 Spec」价值很高。 |
| **是否增加正式编号（如 `15`）？** | **不建议新增 `15` 进入 01～14 主线**，以免与「阶段编号」混淆。若必须文件级命名，可用 **`13-附录-设计交叉校验-R4.md`**（仍归在测试/质量语境）或 **`01-附录-R4-设计交叉校验.md`**（归在元规范/门禁延伸），**不要**占用新的阶段号 `15`。 |
