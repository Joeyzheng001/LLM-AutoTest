## 1. 背景、目标与范围

### 1.1 背景与痛点

> 描述业务方遇到的问题，至少 2~3 条。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | `02` S-01 / S-02 |
| 研报阅读耗时、关键信息提取与多份对比依赖人工 | `02` S-01 / S-03 |
| 涉及投研结论时，缺少可复盘的问答与来源标识，复盘成本高 | 场景推演 |

### 1.2 目标（痛点 → 正面目标）

| 痛点 | 目标 |
|------|------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

### 1.3 提案概要

> 用 2~3 句话概括要做什么。

**示例**：在投研助手场景下，先交付**统一会话入口 + 可降级问答 + 会话历史落库与查询**，为分析师提供可演示、可测试的最小闭环。

### 1.4 范围边界（Phase 分期）

**Phase 1（本版 Must）**：

| 交付块 | 说明 |
|--------|------|
| 会话管理 | 创建、列表、删除会话 |
| 问答提交 | 绑定 `session_id` 的提问；三级降级（CoPaw → 百炼 → Demo） |
| 历史与追溯 | 按会话查看问答记录；响应含 `traceId`、`answer_source` 等 |
| 能力探测 | `GET …/capabilities`，驱动前端能力状态展示 |

**Phase 2（Backlog，本版 Out of Scope）**：

| 方向 | 说明 |
|------|------|
| 研报解析 | PDF/HTML 结构化抽取 |
| 深度问答 | 引用级回答、版权与合规策略 |
| 舆情与对比 | 关键词告警、多研报指标对比 |

**范围内 / 范围外简表**：

| 做（Phase 1 内） | 不做（本版明确不做） |
|-----------------|---------------------|
| 会话管理：创建、列表、删除 | 多租户 / 行级数据权限 |
| 问答编排与可观测字段 | 研报流水线、舆情、对比（见 Phase 2） |
| 本地 JSON 存储的教学级持久化 | 生产级高可用集群与审计日志外发 |

## 2. 用户、场景与规则

### 2.1 目标用户

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 【请填写角色 2】 | 【使用目标】 | 【频率】 |

### 2.2 核心业务场景

> 按用户操作动线拆，每条场景 = 一条动线。

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 查看并切换历史会话 | 侧栏选择会话 → 主区加载该会话问答记录 |
| SC-03 | 了解当前模型与降级状态 | 进入页面或刷新 → Header 能力芯片与 `capabilities` 一致 |
| SC-04 | （Phase 2 占位）研报上传与解析 | **本版不实现** |

### 2.3 产品规则

> 把场景展开成可落地的规则。每条规则给一个编号，后续 US 和 API 会引用。

| 编号 | 规则 | 说明 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 会话隔离 |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 输入约束 |
| R-03 | 成功回答须含 `traceId`、`answer`、`llm_used`、`model`、`response_time_ms`、`answer_source` | 响应契约 |
| R-04 | 降级须按 CoPaw → 百炼 → Demo 顺序尝试，不可跳级 | 降级策略 |
| R-05 | 删除会话须级联删除其下问答记录 | 数据一致性 |

### 2.4 能力与优先级

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-02 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 能力探测与状态展示 | **P1** | SC-03 |
| （Phase 2）研报解析与对比 | **—** | SC-04（占位） |

## 3. 成功标准与风险

### 3.1 成功标准（可度量）

> 写出 3~4 条可量化的验收条件。

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成「新建会话 → 提问 → 查看历史」全链路 |
| 未配置外部模型仍可演示 | 无有效 API Key 时，`answer_source=demo` 且接口不抛未处理异常 |
| 能力状态可解释 | 前端能力芯片与 `GET …/capabilities` 字段一致 |
| 追溯字段齐全 | `POST …/ask` 成功响应含 `traceId`、`llm_used`、`answer_source` |

### 3.2 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |

### 3.3 立项前置条件

- [ ] 后端与前端可独立启动
- [ ] 演示数据目录可读写

### US-001 会话管理

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1QA-001 |
| **故事** | 作为投研分析师，我希望创建和管理多个问答会话，以便按话题分类整理投研问答 |
| **优先级** | P0 |
| **来源** | SC-01, SC-02 |
| **前置条件** | 用户已登录系统 |
| **引用规则** | R-01（session_id 绑定）、R-05（级联删除） |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 用户可以创建新会话，创建后立即出现在左侧会话列表中 |
| AC-001-02 | 用户可以删除已有会话，删除后该会话及其下所有问答记录不可见 |
| AC-001-03 | 用户可以点击会话列表中的任一会话，主区加载该会话的历史问答 |
| AC-001-04 | 未登录状态下无法创建或删除会话，提示"请先登录" |

---

### US-002 问答提交

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1QA-002 |
| **故事** | 作为投研分析师，我希望在会话中提问并获得回答，以便快速获取投研观点 |
| **优先级** | P0 |
| **来源** | SC-01 |
| **前置条件** | 已创建并选中一个会话 |
| **引用规则** | R-02（输入约束）、R-03（响应字段）、R-04（降级策略） |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-002-01 | 用户输入非空问题并提交后，系统在 5 秒内返回回答，回答包含 `answer` 和 `traceId` |
| AC-002-02 | 用户输入为空或超过 500 字符时，系统返回 400 错误，明确提示原因 |
| AC-002-03 | 当所有 LLM 通道不可用时，系统返回 Demo 模式的预设回答，`answer_source=demo` |
| AC-002-04 | 问答记录自动落库，刷新页面后该问答记录仍在 |
