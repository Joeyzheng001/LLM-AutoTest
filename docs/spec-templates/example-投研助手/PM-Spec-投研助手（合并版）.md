## 1. 背景、目标与范围

### 1.1 业务背景与痛点

> 基金投研团队在日常工作中面临以下核心痛点：

| 痛点编号 | 痛点描述 | 影响面 | 来源 |
|----------|----------|--------|------|
| PT-01 | 信息分散：研报、新闻、市场数据分布在多个系统（Wind、iFinD、内部知识库），分析师需频繁切换，无统一问答入口 | 每次查询平均耗时 15-20 分钟，效率损失显著 | 投研团队访谈 |
| PT-02 | 研报阅读耗时长：一份深度研报 50-100 页，关键信息提取、多份研报对比依赖人工 | 核心研报平均阅读时间 2-3 小时/份，影响投研产出效率 | 场景推演 |
| PT-03 | 投研结论缺少可复盘的问答与来源标识：讨论结论散落在邮件、微信、会议记录中，复盘成本高 | 投委会追溯某次观点时，平均需要 1-2 天回溯 | 投研团队访谈 |
| PT-04 | 外部 LLM 通道不稳定：CoPaw 或百炼偶发不可用，无降级兜底策略 | 问答中断影响投研决策时效 | 技术评估 |

### 1.2 业务目标（痛点 → 目标映射）

| 痛点编号 | 业务目标 | 成功标志 |
|----------|----------|----------|
| PT-01 | 统一会话问答入口 | 分析师在一个界面完成所有投研问答，无需切换系统 |
| PT-02 | 快速信息提取 | 问答响应在 5 秒内返回（含来源标识） |
| PT-03 | 会话历史自动沉淀 | 所有问答记录按会话归档，随时回看 |
| PT-04 | 可降级问答链路 | 外部 LLM 不可用时，Demo 模式兜底不中断服务 |

### 1.3 提案概要

在投研助手场景下，**Phase 1 交付统一会话入口 + 可降级问答 + 会话历史落库与查询**，为投研分析师提供可演示、可测试、可复盘的最小闭环。

### 1.4 范围边界（Phase 分期）

#### Phase 1（本期 Must-Have）

| 交付块 | 说明 | 优先级 |
|--------|------|--------|
| 会话管理 | 创建、列表、删除会话，支持按时间排序 | P0 |
| 问答提交 | 绑定 `session_id` 的提问，三级降级（CoPaw → 百炼 → Demo） | P0 |
| 历史与追溯 | 按会话查看问答记录；响应含 `traceId`、`answer_source` 等追溯字段 | P0 |
| 能力探测 | `GET /capabilities` 返回当前可用模型通道状态 | P1 |

#### Phase 2（Backlog，本期 Out of Scope）

| 方向 | 说明 | 不做的原因 |
|------|------|-----------|
| 研报解析 | PDF/HTML 结构化抽取 | 涉及文档解析引擎，复杂度超出 Phase 1 |
| 深度问答 | 引用级回答、版权与合规策略 | 需要投研内容授权，Phase 1 不涉及外部内容 |
| 舆情与对比 | 关键词告警、多研报指标对比 | 属于独立产品模块，不阻塞问答闭环 |
| 多租户权限 | 行级数据权限控制 | 当前用户规模不需要，Phase 2 再考虑 |

#### 范围内 / 范围外简表

| 做（Phase 1 内） | 不做（本期明确不做） |
|-----------------|---------------------|
| 会话管理：创建、列表、删除 | 多租户 / 行级数据权限 |
| 问答编排与三级降级 | 研报流水线、舆情、对比（见 Phase 2） |
| 本地 JSON 存储的教学级持久化 | 生产级高可用集群与审计日志外发 |
| 能力探测与状态展示 | 用户认证与权限体系（本期免登演示） |

## 2. 用户、场景与产品规则

### 2.1 目标用户

| 角色编号 | 角色名称 | 使用目标 | 使用频率 | 核心诉求 |
|----------|----------|----------|----------|----------|
| U-01 | 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 | 响应快、来源可信 |
| U-02 | 投研团队负责人 | 复盘团队讨论与观点沉淀 | 每周 2-3 次 | 会话可追溯、可回看 |
| U-03 | 投研运营（可选） | 查看系统可用性与使用情况 | 每天 | 能力状态可监控 |

### 2.2 核心业务场景

> 按用户操作动线拆分，每条场景 = 一条端到端动线。

| 场景编号 | 场景名称 | 涉及角色 | 用户路径 | 优先级 |
|----------|----------|----------|----------|--------|
| SC-01 | 新建会话并提问 | U-01 | 点击"新会话" → 输入问题 → 获得回答（含来源标识） → 回答自动落库 | P0 |
| SC-02 | 查看并切换历史会话 | U-01, U-02 | 侧栏选择会话 → 主区加载该会话的问答记录 → 可滚动查看 | P0 |
| SC-03 | 了解当前模型与降级状态 | U-01, U-03 | 进入页面或刷新 → Header 能力芯片与 `capabilities` 接口返回一致 | P1 |
| SC-04 | 删除会话 | U-01 | 选择会话 → 点击删除 → 确认 → 会话及下挂问答记录同步删除 | P0 |
| SC-05 | 空状态与错误处理 | U-01 | 无会话时展示引导 → 提问失败时展示明确错误信息 → 可重试 | P1 |

### 2.3 产品规则

> 把场景展开成可落地的业务规则。每条规则给一个编号，后续 UserStory、API、测试用例均引用此编号。

| 规则编号 | 规则名称 | 规则描述 | 规范级别 | 影响范围 |
|----------|----------|----------|----------|----------|
| R-01 | 会话隔离 | 每条提问必须绑定 `session_id`，不同会话之间的问答记录互不可见 | MUST | 问答提交、历史查询 |
| R-02 | 输入约束 | `query` 长度 1～500 字符，为空或超长返回明确错误提示 | MUST | 问答提交 |
| R-03 | 响应契约 | 成功回答须含 `traceId`（字符串，唯一）、`answer`（字符串）、`llm_used`（布尔值，是否使用外部 LLM）、`model`（字符串，模型名称）、`response_time_ms`（整数，毫秒）、`answer_source`（枚举：copaw/bailian/demo） | MUST | 问答响应 |
| R-04 | 降级策略 | 降级须按 CoPaw → 百炼 → Demo 顺序尝试，不可跳级；任一通道成功后即返回，不再尝试下一级 | MUST | 问答编排 |
| R-05 | 级联删除 | 删除会话须级联删除其下所有问答记录，不可遗留孤儿记录 | MUST | 会话删除 |
| R-06 | 会话标题 | 新建会话时，以用户的第一条提问内容前 20 个字符作为会话标题 | SHOULD | 会话创建 |
| R-07 | 排序规则 | 会话列表按创建时间倒序排列（最新在前）；问答记录按创建时间正序排列（最早在前） | SHOULD | 列表展示 |
| R-08 | 来源标识展示 | 前端须在回答旁展示来源标识：CoPaw（绿色）、百炼（蓝色）、Demo（灰色） | SHOULD | 前端展示 |
| R-09 | Demo 回答内容 | Demo 模式的预设回答为："当前外部模型不可用，以下为演示回答：{问题关键词}相关的投研观点包括……" | MUST | 问答降级 |

## 3. 成功标准与风险

### 3.1 成功标准（可度量）

| 标准编号 | 标准描述 | 度量方式 | 目标值 |
|----------|----------|----------|--------|
| SS-01 | 主路径可走通 | 投研分析师在 3 分钟内完成「新建会话 → 提问 → 查看历史」全链路 | ≤ 3 分钟 |
| SS-02 | 未配置外部模型仍可演示 | 无有效 API Key 时，`answer_source=demo` 且接口不抛未处理异常 | 100% 可用 |
| SS-03 | 能力状态可解释 | 前端能力芯片展示的可用通道与 `GET /capabilities` 返回完全一致 | 字段一致 |
| SS-04 | 追溯字段齐全 | `POST /ask` 成功响应中 `traceId`、`llm_used`、`answer_source` 三个字段均不为空 | 100% |
| SS-05 | 问答响应时效 | 从提问到返回回答（含 Demo 模式），响应时间不超过 5 秒 | ≤ 5000ms |

### 3.2 风险识别

| 风险编号 | 风险描述 | 影响 | 概率 | 应对策略 | 责任人 |
|----------|----------|------|------|----------|--------|
| RK-01 | 外部 LLM 不可用 | 问答功能降级 | 中 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 | 研发 |
| RK-02 | 问答内容不准确 | 投研决策依据错误 | 低 | Demo 回答中明确标注"演示回答"，不暗示权威性 | PM |
| RK-03 | 会话数据丢失 | 历史记录不可回看 | 低 | 每次问答立即落盘 JSON 文件；删除操作需二次确认 | 研发 |
| RK-04 | 前端展示与后端返回不一致 | 用户看到的信息不准确 | 中 | 来源标识颜色与 `answer_source` 枚举值一一对应 | PM + 前端 |

### 3.3 依赖项

| 依赖编号 | 依赖描述 | 提供方 | 状态 |
|----------|----------|--------|------|
| DEP-01 | CoPaw API Key | 技术团队 | 待确认 |

### US-001 会话管理

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1QA-001 |
| **故事** | 作为投研分析师，我希望创建和管理多个问答会话，以便按话题分类整理投研问答 |
| **优先级** | P0 |
| **来源场景** | SC-01, SC-02, SC-04 |
| **前置条件** | 用户已打开投研助手页面 |
| **引用规则** | R-01（会话隔离）、R-05（级联删除）、R-06（会话标题）、R-07（排序规则） |

| 验收标准编号 | 验收标准描述（每条可独立测试） |
|--------------|-------------------------------|
| AC-001-01 | Given 用户在投研助手页面，When 点击"新会话"按钮，Then 左侧会话列表立即出现一条新会话记录 |
| AC-001-02 | Given 用户创建新会话，When 查看会话标题，Then 标题为"新会话"（第一条提问后更新为提问内容前 20 字符） |
| AC-001-03 | Given 用户删除已有会话，When 确认删除操作，Then 该会话从列表中消失，且该会话下所有问答记录不可见 |
| AC-001-04 | Given 用户有多个会话，When 查看会话列表，Then 会话按创建时间倒序排列（最新创建的在最上方） |
| AC-001-05 | Given 用户点击会话列表中的任一会话，When 选中该会话，Then 主区加载并显示该会话的历史问答记录 |
| AC-001-06 | Given 页面无任何会话，When 用户进入页面，Then 展示空状态引导文案"点击新建会话开始投研问答" |

### US-002 问答提交

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1QA-002 |
| **故事** | 作为投研分析师，我希望在会话中提问并获得回答，以便快速获取投研观点 |
| **优先级** | P0 |
| **来源场景** | SC-01 |
| **前置条件** | 已创建并选中一个会话 |
| **引用规则** | R-02（输入约束）、R-03（响应字段）、R-04（降级策略）、R-09（Demo 回答） |

| 验收标准编号 | 验收标准描述（每条可独立测试） |
|--------------|-------------------------------|
| AC-002-01 | Given 用户在会话中输入非空问题并提交，When 系统处理请求，Then 在 5 秒内返回回答，回答包含 `answer` 文本和 `traceId` |
| AC-002-02 | Given 用户输入为空（空白字符或空字符串），When 点击提交，Then 系统返回 400 错误，前端展示"请输入问题内容" |
| AC-002-03 | Given 用户输入超过 500 字符，When 点击提交，Then 系统返回 400 错误，前端展示"问题长度不能超过 500 字符" |
| AC-002-04 | Given 所有外部 LLM 通道（CoPaw、百炼）均不可用，When 用户提交问题，Then 系统返回 Demo 模式的预设回答，`answer_source` 值为 "demo" |
| AC-002-05 | Given CoPaw 通道可用，When 用户提交问题，Then 系统优先调用 CoPaw，返回回答中 `answer_source` 为 "copaw"，`llm_used` 为 true |
| AC-002-06 | Given CoPaw 不可用但百炼可用，When 用户提交问题，Then 系统自动降级到百炼，返回回答中 `answer_source` 为 "bailian" |
| AC-002-07 | Given 用户提交问题并获得回答，When 刷新页面后重新进入该会话，Then 该问答记录仍然存在（已落库持久化） |
| AC-002-08 | Given 用户成功获得回答，When 查看回答内容，Then 回答旁展示来源标识：CoPaw（绿色标签）、百炼（蓝色标签）、Demo（灰色标签） |

## 6. 术语表

| 术语 | 定义 |
|------|------|
| 会话（Session） | 一次连续的问答上下文，包含多条问答记录 |
| 问答记录（QA Record） | 一次提问和对应的回答，绑定到一个会话 |
| 追溯标识（traceId） | 每次问答请求的唯一标识，用于日志追踪和复盘 |
| 来源标识（answer_source） | 回答来自哪个通道：copaw（CoPaw）、bailian（百炼）、demo（演示模式） |
| 降级（Fallback） | 当高优先级 LLM 通道不可用时，自动切换到低优先级通道 |
| 能力探测（Capabilities） | 系统对外暴露的当前可用模型通道状态信息 |
