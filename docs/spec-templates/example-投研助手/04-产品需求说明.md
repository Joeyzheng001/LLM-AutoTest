## 3. 核心业务场景

> 把 `03` 第 2 节提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 查看并切换历史会话 | 侧栏选择会话 → 主区加载该会话问答记录 |
| SC-03 | 了解当前模型与降级状态 | 进入页面或刷新 → Header 能力芯片与 `capabilities` 一致 |
| SC-04 | （Phase 2 占位）研报上传与解析 | **本版不实现**；见 `03` Phase 2 |

## 4. 产品规则

> 把 `03` 第 4 节成功标准与第 3 节范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | `03` Phase 1 问答 |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | `03` 成功标准（可测） |
| R-03 | 成功回答须含 `traceId`、`answer`、`llm_used`、`model`、`response_time_ms`、`answer_source` | `09` 问答响应表 |
| R-04 | 降级须按 CoPaw → 百炼 → Demo 顺序尝试，不可跳级；通过 `answer_source` 标识 | `03` Phase 1 |
| R-05 | 删除会话须级联删除其下问答记录（与 `10` 一致） | 数据一致性 |

## 5. 能力与优先级

> `03` 第 3 节范围表写了「做什么」，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-02 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 能力探测与状态展示（Header 芯片） | **P1** | SC-03 |
| （Phase 2）研报解析与对比 | **—** | SC-04（占位，本版不交付） |

## 6. 验收与成功标准（PRD 层）

> 从 `03` 第 4 节可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 能力一致 | Header 展示与 `GET /api/v1/agent/capabilities` 返回一致 |
| Phase 2 不混入验收 | 不出现「解析 PDF」等未在 `09` 定义端点的硬门禁 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| 第 3 节 核心场景 | 一条叙事场景 → 一条或多条 US | 如 SC-01 → US-001 + US-002 |
| 第 4 节 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| 第 5 节 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
