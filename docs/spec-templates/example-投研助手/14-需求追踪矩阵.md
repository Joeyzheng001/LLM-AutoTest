**需求（REQ）↔ 用户故事（UserStory）↔ API 端点 ↔ 测试用例（TC）**

> 变更需求时，沿链路定位受影响的用户故事、API、测试用例。  
> **API 列**：写全路径；与 `09` 中「简写」对照见 `09` 第 1.1 节。

## 1. 需求编号体系

| 编号格式 | 含义 | 示例 |
|----------|------|------|
| `REQ-M1QA-{NNN}` | 功能需求（**与 `05` / `13` 同一前缀**） | `REQ-M1QA-002` |
| `RULE-M1-{NNN}` | 数据 / 类型约束（DTO 层） | `RULE-M1-001` |

| 级别 | 含义 | 门禁影响 |
|------|------|----------|
| **P0** | 必须实现，阻塞发布 | 关联测试用例全绿方可合并 |
| **P1** | 应当实现，不阻塞首版 | CI warning |
| **P2** | 可选增强 | 不纳入门禁 |

## 2. 需求定义表

> 每条需求对应一个可测试的需求点。从 `05` 用户故事与 `09` API 提取。

| 需求编号 | 需求名称 | 优先级 | 来源 | 详细说明 |
|----------|----------|--------|------|----------|
| **REQ-M1QA-001** | 会话管理 CRUD | P0 | `05` US-001 | `GET/POST /api/v1/agent/sessions`、`DELETE /api/v1/agent/sessions/<id>` |
| **REQ-M1QA-002** | 问答提交与响应契约 | P0 | `05` US-002 | `POST /api/v1/agent/ask`：成功体字段、`EMPTY_QUERY` / `INVALID_QUERY`、无密钥时 Demo 降级 |
| **REQ-M1QA-003** | 按会话查看问答记录 | P0 | `05` US-003 | `GET /api/v1/agent/sessions/<id>/records` |
| **REQ-M1QA-004** | 能力探测与配置状态 | P1 | `05` US-004 | `GET /api/v1/agent/capabilities` |
| **RULE-M1-001** | `llm_used` 类型约束 | P0 | `09` 响应 DTO | 必须为 boolean |
