## 二、定稿目标（冻结口径）

| # | 目标 | 定稿要点 |
|---|------|----------|
| G1 | 可运行系统 | 5 协议 × 6 环节闭环；「跑通」= 端到端执行完成 + 结构化产物 + 断言二态明确；降级场景不计入「跑通」，仅标注为「路径演示」 |
| G2 | 需求文档解析 | Word / Markdown / Excel 三格式各 1 份样例解析成功；比对基准为预置 golden 基准（非现场人工判断） |
| G3 | 接口逆向解析 | 指定 Java 多仓库（≥2 个）扫描与还原；**兜底仓库结果单独标注、不计入 G3 达成、与真实仓库结果分列** |
| G4 | Code Review 三视图 | 映射表 + 风险清单 + 遗漏功能清单，一次生成、三种视图 |
| G5 | 自动化率实测 | 9 节点口径，分母固定为 9；判读框架：≥70% 高（建议规模化）/ 30–70% 中（按瓶颈选择性投入）/ <30% 低（瓶颈治理为前置条件） |
| G6 | 周期约束 | 一周内完成全部交付，按 M0–M5 里程碑逐日核对 |

**G1 为核心目标，G6 为刚性约束，G2–G5 为验收细节。**

## 四、范围冻结快照

### 4.1 范围内（MVP）

- **输入通道**：需求文档三格式解析（Word/Markdown/Excel）+ Java 多仓库扫描与 LLM 接口逆向（唯一接口来源）
- **流水线 6 环节闭环**：Code Review → 用例生成 → 自动执行 → 测试报告 → 缺陷清单（本地文件）→ 回归沉淀，另含复测与人工审核（E-REVIEW-03）
- **协议范围**：REST / gRPC / GraphQL / SOAP / MQ 全覆盖（最小可用级，允许按 R3 策略降级；MQ 以降级路径为主方案）
- **度量体系**：9 节点口径 + 半自动采集 + 一次实测 + 瓶颈分析
- **技术基线**：GLM-5.3（不新增模型投入）；测试框架项目内选型
- **团队可用 Web 界面**（V2.1 增量）：Vue 3 前端，页面方向按 [07_UI演示设计.md](07_UI演示设计.md) 六页；CLI 统一入口（F-ORCH-01）口径保持不变，Web 与 CLI 并存

### 4.2 范围外（非目标 N1–N10，冻结）

生产级成熟度打磨（N1）、UI/性能/安全测试（N2）、LLM 训练/微调（N3）、幻觉系统性应对（N4）、接口文档治理（N5）、合规/安全审查建设（N6）、历史数据资产建设（N7）、跨团队推广（N8）、**缺陷管理系统对接（N9）**、**需求变更增量处理（N10）**。

### 4.3 实现深度约定

- **P0 卡片（7 张）**：完整实现
- **P1 卡片（8 张）**：最小可用实现（每卡片 1 个最小场景）
- 人力基线：4 人全时投入（A 测试架构师 / B、C 测试开发 / D 测试工程师），对应排期 M0–M5

## 六、变更控制规则（冻结后生效）

1. **冻结原则**：自本文件签署起，基线四文档（01–04）不再接受需求级变更；实施过程中发现的问题优先按现有口径消化（降级、路径演示、非目标排除均已预留通道）。
2. **允许的例外变更**（不计为需求变更）：
   - 测试框架选型结论（G 范围内授权项目内自选）；
   - 演示仓库的选择与切换（按 D5 口径执行，不影响目标定义）；
   - R1 范围检查点触发的降级决策（按 R1 应对策略与 X-EXEC-03 执行，报告中注明）。
3. **必须走变更控制的情形**：影响 G1–G6 任一目标的达成判定、9 节点口径、N1–N10 非目标边界、一周刚性周期（G6）的任何调整。处理流程：提出方书面提出 → 测试团队负责人裁决 → 修订基线文档并升版（V1.x）→ 同步更新本冻结文档的裁决记录。
4. **规模化的前置输入**：若本项目后进入规模化阶段，N9（缺陷系统对接）、N10（需求变更增量处理）、Prompt 回归验证集（TA-05 移除项）应作为该阶段需求的候选项重新立项，本基线不预支。
