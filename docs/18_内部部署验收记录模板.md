# 内部部署验收记录模板

> 用于部门内部服务器首次上线、版本升级和灾备演练。模板中的“通过”必须附命令输出、截图、日志或
> 产物路径；本地单元测试只能证明代码行为，不能替代真实服务器验收。不得在本记录中填写密码、API Key、
> 访问令牌或 Git Token。

## 2. 发布前配置与安全门禁

| 检查项 | 命令或证据 | 状态 |
|---|---|---|
| `.env` 来自密钥系统或受控目录，未进入 Git | `git status --short -- deploy/.env`；密钥管理记录 | 待执行 |
| Compose 配置可展开 | `docker compose --env-file deploy/.env -f deploy/docker-compose.department.yml config --quiet` | 待执行 |
| 部署预检通过 | `docker compose ... run --rm --no-deps orchestrator uv run python -m orchestrator validate-deployment` | 待执行 |
| SecretStore 主密钥已配置 | 预检摘要 `secrets_store=enabled`，不粘贴密钥 | 待执行 |
| 访问令牌映射和项目范围已配置 | 预检摘要；不粘贴令牌 | 待执行 |
| `DATABASE_URL` 为完整 URL，密码已 URL 编码 | 预检摘要；不粘贴连接串 | 待执行 |
| 入口生产证书有效 | 浏览器/证书链检查；不使用 `--insecure-tls` | 待执行 |

## 3. 启动与就绪

```sh
COMPOSE_ENV_FILE=deploy/.env APP_URL=https://<部门入口> \
  sh deploy/department_bootstrap.sh
```

## 4. 多实例与任务可靠性

| 检查项 | 验证方式 | 状态 / 证据 |
|---|---|---|
| 同一任务不会被两个 Worker 同时领取 | 提交一个只读/短任务，核对数据库租约和两实例日志 | 待执行 |
| 租约过期可接管 | 在隔离任务上停止持有实例，观察另一实例接管；不得重复调用已完成批次 | 待执行 |
| 数据库优先读取 | 临时让一个实例不可见本地 `state.json`，任务列表/详情仍可查 | 待执行 |
| 运行日志跨重跑保留 | 重跑后确认当前轮与历史轮次均可见，敏感字段已脱敏 | 待执行 |
| 任务停止/断点重跑 | 停止后从指定节点恢复，核对 checkpoint 与产物归档 | 待执行 |
| LLM 批次复用 | 中断 `testcase_generate` 后重跑，已成功批次不重复消耗调用 | 待执行 |
