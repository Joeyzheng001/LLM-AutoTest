## 已修复的问题

| 原因 | 修复 |
|---|---|
| `accountNo`、`GroupList`、`riskChannel` 被误判为内部状态 | 从接口参数、直接 JSONObject 读取和源码常量确定 body 所属参数，再归一为 `param.xxx`；保留路径参数，拒绝未知或多义字段。 |
| 引文存在就被当作断言正确 | 为 LLM 提供程序提取的完整 if 条件与 `branch_id`；检查条件来源、简单比较和请求值；下游/配置/注册表分支检查控制夹具。 |
| 任意场景文字绕过下游依赖检查 | 控制来源沿局部赋值、循环别名及集合写入传播，不依靠场景中的“结果为空”等词命中门禁。无法证明的来源保留缺口。 |
| `return response` 被当作字段不存在的证据 | `not_exists` 要求字段删除或序列化忽略证据；普通 return/setter 不足以证明字段缺失。 |
| 只有字段存在断言就直接隔离 | 对可修复候选单独请求补充业务断言，再复核；其它有效候选不受影响。 |
| 同一请求满足宽泛条件，就把另一个分支记为已覆盖 | 运行契约合并还需核对请求来源分支和源码引用；不能把下游 null 分支合并成入口参数错误。 |
| 已观测请求被模型扩写成重复用例，挂到无关 Claim | 运行观测契约按精确输入确定性生成，不送入模型展开；拒绝参数变体，使用实际场景标题，清除无证据的需求/Claim/测试点关联。 |
| 修改代码后旧服务继续使用新提示词 | 服务公开启动指纹；代码、提示词或契约与已加载版本不一致时，新任务返回 409，要求先重启。 |
| 仅保存摘要，无法复现 LLM 误判 | 保存完整 system/user/原始回答，文件权限 0600，并在调用记录关联文件；保留现有完整分页和输出续接机制。 |
| 历史 Windows 路径导致当前系统源码范围匹配失败 | 在公共路径归一入口处理反斜杠，兼容旧任务产物。 |
| CLI 没有 API 的配置文件导致节点异常 | 无 `job_input.json` 时使用关闭主动探测和造数的默认配置。 |

分支提取与来源传播是保守的源码检查，不是完整 Java 控制流证明。复杂条件、无法绑定的调用和外部状态仍需补充证据或组件测试；不会因此自动放宽准入。
