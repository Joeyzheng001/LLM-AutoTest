# E2E 业务测试实现说明

更新：2026-10-21。对应协议 `contract_version=2.0`。后续修改代码时必须同步维护本文及相关协议。

## 1. 任务入口与边界

前端“E2E 业务测试”工作台提供业务用例、执行报告、Bug 记录、回归资产四个页签。独立流程读取已有任务的 `requirement_items.json` 与 E2E 配置，不读取 API oracle，不要求九节点先完成。原九节点中的 E2E 开关仍保留，但它的调用顺序仍在 API 生成之后；希望独立运行应使用工作台。

当前提供任务级地址配置入口；多角色、数据准备资源和文件资源由任务 E2E 配置接口填写。尚未提供完整的可视化资源编辑器。

## 2. 独立 API

所有端点均沿用任务访问控制、任务队列及互斥锁；运行任务期间不并发修改同一任务。

|方法与路径（前缀 `/api/v1/jobs/{job_id}`）|作用|
|---|---|
|`PUT /e2e/configuration`|保存前端地址及身份、资源、探索策略|
|`GET /e2e`|读取操作状态和当前步骤进度|
|`POST /e2e/generate`|生成，`resume=true` 复用捕获的页面证据|
|`POST /e2e/execute`|执行全部或 `case_ids` 指定用例|
|`POST /e2e/run`|依次生成和执行|
|`POST /e2e/retest`|以 `defect_ids` 选择缺陷，执行其原始用例快照|
|`POST /e2e/regress`|以 `fingerprints` 选择历史回归版本并执行|

修改代码后运行接口检查服务版本，旧进程会返回需要重启，避免前端以为正在使用新逻辑。公司模型沿用任务配置和密钥回退；生成与重新定位都使用该客户端。

## 3. 完整输入与模型分工

1. 浏览器捕获页面文本、全部候选控件、选项、顶层/iframe 归属与截图。新版观察不截取正文或控件列表。
2. 从需求 Claim 派生 UI 规则；无 Claim 时使用需求描述。每条规则保存原文及验收标准。
3. 按规则并行召回完整页面目录，默认并发 4；一条规则内先规划场景，再读取定位事实，再逐场景生成用例，并调用同一个任务模型逐条复核独立准备、页面切换和最终业务检查。复核失败保留原草稿和诊断，不让有效草稿无声消失。执行默认串行，避免共享业务数据互相干扰。
4. 大输入按路径和值拆成完整分页；能放下的控件对象作为完整一行，避免把标签和定位器拆散。长字符串保留全部带偏移片段，不做字符尾部截断。每页有编号与摘要，保存阅读清单；相同规则的同组页面定位结果复用。
5. 无效的可选定位事实逐项保留诊断并忽略，执行时重新观察，不将其等同于源码/页面未读取；无法读取的整页仍保留缺口。单页没有匹配是目录阅读备注；整条规则没有场景才算覆盖缺口。读取失败和生成失败持续保存，断点续跑不把半成品标记完成。
6. 模型 JSON 修复使用相同输入、明确错误及上一轮完整输出；公共模型客户端负责响应续传和完整审计。修复不能修改需求预期。

按规则并行不等于浏览器所有路径已经穷尽。页面探索沿用部分菜单遍历辅助逻辑，菜单层级和交互预算仍由配置控制；未探索内容保留 pending。动态弹窗和控件允许在执行时继续观察、定位。

## 4. 用例协议

每条用例包含需求、`rule_refs`、类型、角色、前置条件、`setup`、`precondition_checks`、`steps`、`cleanup`、文字预期及执行阻断原因。

业务步骤中的每个断言必须引用有效规则和逐字原文 `basis`。固定文本预期须来自该规则原文，不能以当前页面文本替代；复核阶段按业务断言内容对账，禁止删改原动作/预期值及需求归属，只可改定位、补准备及新增有依据的检查。单规则批次中省略的需求编号和断言归属由程序绑定该输入规则；已有错误引文仍须修复，不把无依据值编成预期。缺少独立 target_intent 但已有业务 intent 时自动复用意图，不要求模型重复填相同文字。准备、登录、可达性检查属于就绪检查，不贡献业务通过结论，也不要求伪造需求引文。至少一条业务结果断言，只有点击或 URL 检查不能通过。

支持正常、边界、异常、权限、状态流转、数据一致性六类。场景由需求决定，不给所有功能机械套维度，不设置固定用例条数。

数据条目的存在性检查可用当前可见的原生选择控件及唯一真实 option 共同证明，并记录 option_present；需求明确规定按钮形态时不做该适配。已有定位器与更明确的原意图冲突时，可用当前唯一实际控件匹配修正定位，不修改断言值。

定位使用语义控件、容器 `within`、frame、窗口名。设计时未出现的字段使用 `target_intent`；运行时先核对原意图中逐字匹配且唯一的真实控件名称/原生下拉选项，不能确定时再调用任务模型从完整观察中定位，保留业务输入和断言。组合 combobox/option 定位仅在实际选项唯一可核验时适配为原生选择，原模型输出完整保留。原意图点击指定条目、现场却是原生下拉时，允许模型返回受控 select_value；程序必须验证实际选项及其值/标签在原意图中出现，才将点击适配为选择操作。唯一 frame 归属可由浏览器事实校正；歧义保留，不猜。模型无法任意执行 JavaScript。

动作涵盖导航、点击、填充、选择、键盘、悬停、滚动、拖拽、上传/下载、多窗口、多身份、变量提取及配置资源准备；断言涵盖文本、值、数量、可见性、可操作性、选项及业务响应。任意数据造数或数据库修改不由模型自由执行，只可引用任务配置资源。

## 5. 身份、数据与执行

- 每条用例隔离浏览器上下文；默认身份、匿名和命名角色分开。没有配置命名角色且场景不涉及权限分离时，模型从页面用户名推测的角色名映射到任务默认身份；权限场景缺少真实角色配置仍保留阻断。匿名不继承登录态。
- 多身份使用 `open_actor`，通过运行变量共享真实业务记录编号；同源鉴权头仅注入当前站点。
- 账号密码加密保存，任务 JSON 只存非敏感配置。证据按敏感字段和配置凭据脱敏；密码框及标记的敏感区域截图遮罩。
- 运行变量包括 `RUN_ID`、`CASE_ID`、`UNIQUE`，及提取变量。历史业务 ID 不凭空编造。
- 每步执行前后捕获截图和页面状态。定位失效可重新读取现场、调用模型重新定位；已经提交的动作发生超时后不自动重放，避免重复操作。
- 失败后仍执行清理。清理失败单独保留，不能把未清理成功算完整通过。
- Playwright Trace 含原始浏览器信息，只在显式 `retain_trace=true` 时保留；默认保留脱敏的截图、页面状态、网络和控制台。

## 6. 判定与证据

业务断言失败、环境失败、自动化问题、前置阻断、待执行、待判定和通过分别统计。所有计划用例先登记占位记录，未发送操作也不从总数消失。前置检查失败不创建产品 Bug。

执行时实时保存步骤进度。每次运行独立 `run_id`，路径：

```text
evidence/e2e/{run_id}/{case_id}/
  STEP-...-before.png / STEP-...-after.png
  STEP-...-before-state.json / STEP-...-after-state.json
  progress.json / network.json / console.json / result.json
```

实际文件名按执行器 step_id 生成。聚合产物是 `e2e_design.json`、`e2e_execution.json`、`e2e_defects.json`、`e2e_history.json`、`e2e_regression.json`。每个执行批次另存结果快照和 HTML 报告。导出 ZIP 包含全部引用证据；HTML 位于原目录层级，解压后可离线查看截图。

报告按类型着色并显示文字标签，支持筛选。E2E 的任务选择器不混入九节点计数，任务结束后刷新运行标记；本次计划数单独展示，与当前执行结果分类对账。通过用例同样可以展开每步预期/实际及截图，失败步骤优先展开；全量网络和控制台记录按需加载。

## 7. Bug 与复测、回归

只有业务断言失败生成待确认产品缺陷。保存失败步骤、预期/实际、身份、准备和清理、全部证据引用、用例和执行快照、发生次数和状态历史。环境或定位失败保留运行记录，不直接制造产品 Bug。

缺陷复测使用原始用例快照；环境阻断不会自动关闭缺陷。通过后标为建议关闭；同一失败步骤仍失败才标记保留，其他步骤提前失败记为原缺陷尚未完成复验。多个历史用例共用显示编号时按原始快照区分执行，禁止用最后一个版本替代全部。泛用 REST 缺陷复测路径跳过浏览器用例，避免把缺少 REST 脚本当作 E2E 复测结论。

同一设计版本与用例指纹至少两次证据完整地通过后保存回归快照。当前规则是至少两次，不声称连续两次。重复验证不增加同一快照版本号；修改设计后使用新指纹及版本。工作台可执行指定历史版本；断言不会因页面当前显示内容不同而自动更改。

## 8. 当前限制

- 完整客户业务验收仍需真实业务需求、被测前端、账号和可准备的数据。这不妨碍整体架构实现，但本机技术验证不能代替客户业务验收。
- 尚无视觉识别执行 canvas 的能力；控件需要可观察的 DOM/可访问性语义。
- 角色、资源的配置编辑器及跨任务资产库、外部 Bug 平台同步尚未实现。
- 运行时定位使用 DOM，错误预期不能由恢复逻辑改成实际值；无法确定目标时保留问题。
- 不承诺自动理解缺失的业务规则、无限穷尽状态、自动控制未接线的下游、自动满足外部验证码。

## 9. 代码入口

- `common/e2e_contracts.py`：共享协议和需求规则、完整分页。
- `executor/e2e/explorer.py`：页面观察与归属。
- `executor/e2e/planner.py`：任务模型规划、事实读取、生成与现场定位。
- `executor/e2e/runtime.py`：执行与逐步证据。
- `executor/e2e/reporting.py`：汇总、缺陷、离线 HTML。
- `executor/e2e/service.py`：独立生成、执行、复测、回归流程。
- `orchestrator/api.py`：任务接口、凭据及版本检查。
- 前端 `E2eWorkspace.vue` / `BrowserEvidence.vue`：独立工作台与证据交互。
