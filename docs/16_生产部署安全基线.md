# 生产部署安全基线

本文件对应 P0-06 的 Secret Store 交付，目标是让部门共享部署具备明确的密钥、目录和日志边界。

## 必须配置

生产环境必须设置：

```bash
SECRETS_ENCRYPTION_KEY=<Fernet key>
DATABASE_URL=postgresql+psycopg://<user>:<url-encoded-password>@<host>:5432/<db>
AUTOTEST_ACCESS_TOKENS_JSON={"token-value":{"user_id":"alice","projects":["fund"],"max_concurrent_jobs":2,"daily_job_limit":20}}
```

生成 Fernet 主密钥：

```bash
uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

主密钥只能由部署平台 Secret/KMS 注入，不得写入仓库、镜像、`job_input.json`、日志或导出包。启动日志只显示 `secrets_store=enabled/disabled`，不显示密钥内容。

部门版 `docker-compose.department.yml` 会在启动前强制要求该变量和
`AUTOTEST_ACCESS_TOKENS_JSON` 非空，避免遗漏密钥或访问控制时静默回退到兼容模式；
本地开发环境可以保留兼容路径，但不能作为部门部署验收依据。

`deploy/docker-compose.department.yml` 要求通过 `DATABASE_URL` 注入完整 SQLAlchemy 连接串，
不再在 Compose 内拼接数据库密码。密码包含 `@`、`:`、`/`、`#`、`%` 等 URL 保留字符时，
必须先做百分号编码；`POSTGRES_PASSWORD` 仍需与连接串中的解码后密码一致。

配置 `AUTOTEST_ACCESS_TOKENS_JSON` 后，所有 `/api/v1/*` 请求（健康检查除外）必须携带 `Authorization: Bearer <token>`，并通过 `X-Project-Id` 选择项目；用户身份和项目范围来自服务端令牌映射，不能由请求体伪造。任务列表、状态、配置、报告、导出、重跑、停止、复测和审核接口均执行 owner/project 校验。令牌可选声明 `max_concurrent_jobs` 与 `daily_job_limit`，超限提交返回 429；缺省表示不启用该项配额。

前端顶栏提供共享访问配置，令牌和项目标识只写入当前浏览器会话的 `sessionStorage`，不会写入 `localStorage`、任务配置、日志或导出包；清除会话或点击“断开”后不再发送认证头。生产验收必须使用真实部门令牌验证任务列表、配置、报告和导出请求。

服务探活分为：`/health` 仅表示进程存活，`/ready` 表示已具备接收任务的数据库条件；Prometheus 抓取 `/metrics` 时只会得到固定路由、队列和依赖状态指标，不包含任务内容和凭据。

部署侧可直接参考 `deploy/prometheus/` 的抓取与告警样例；`deploy/load_smoke.py` 只压测 `/ready` 等只读端点，业务/LLM 吞吐压测必须在隔离环境中执行。

## 任务密钥边界

- 启用主密钥后，鉴权密码和 MiniMax API Key 写入 `<artifacts_root>/<job_id>/.job-credentials.enc`；文件内容为 Fernet 密文；
- `job_input.json` 只保留登录地址、用户名、模型、Base URL、Token 上限等非敏感配置；
- 导出接口不包含 `job_input.json` 和 `.job-credentials.enc`；运行日志、数据库事件和日志查询出口统一脱敏；
- 服务重启后可以从密文恢复任务重跑、全量复测和单条复测，不要求用户再次填写密钥；
- 主密钥错误或密文损坏时，任务必须停止并提示“任务密钥不可用”，不得静默按未鉴权/空 API Key 继续执行。

## 密钥轮换

当前版本采用单主密钥读取。轮换时应按以下顺序执行：

1. 备份任务目录和数据库；
2. 在维护窗口使用旧密钥解密并重新写入新密钥；
3. 完成一条历史任务的“读取配置 → 重跑 → 单条复测”验收；
4. 再撤销旧密钥。

后续 P1 运维项可增加 `key_id` 和双密钥过渡期，避免一次轮换阻塞所有历史任务。

## Windows 部署

Windows 不把 Unix `0600` 当作完整安全边界。服务应使用专用 Windows 服务账户运行，并通过 NTFS ACL 将 `artifacts_root` 授权给该账户，禁止普通部门用户直接读取任务目录；用户只通过 Web API 读取脱敏后的配置和结果。
