# 03 需求证据召回

[返回目录](README.md) · [上一步](02-evidence-and-scan-coverage.md) · [下一步：需求审查](04-claim-assessment.md)

## 目的与分工

为一条 Claim 选择语义相关的源码。程序组织完整证据分页、校验编号并合并结果；LLM 判断相关性。这一步不直接判定需求是否实现。

## 输入与输出

输入：当前 Claim、全部接口简表、初始证据目录。

输出：选中的原始完整证据列表，交给步骤 04。分页传输的片段不替代原始证据。

## 当前处理过程

1. `_select_interfaces_for_claims` 当前返回全部接口，不先按相关性裁掉接口。
2. 排除已标为不完整的源码证据。
3. 长源码按连续片段拆分，单片目标上限为 8,000 字符；所有片段都保留，带片段序号。
4. 证据目录按约 12,000 序列化字符的预算分批，逐页调用 `code_review_evidence_select`。
5. 模型返回当前 Claim 编号和选中的证据编号。
6. 程序核对 Claim 编号及引用是否属于当前页；合并各页选中的编号。
7. 按编号取回原始证据，再交给下一步骤按接口审查。

这里的预算是内容分页依据，不是模型 token 上限，也不是把源码只保留前几千字符。单个 JSON 实体可以独占一批并超过预算。

## 并行调度（2026-10-20）

不同 Claim 的完整召回与审查流程以有界 worker 并行执行，服务配置 `CODE_REVIEW_MAX_CONCURRENCY` 默认 4，设为 1 可串行。单条 Claim 内的召回页仍依次调用，全部召回结束后才开始该 Claim 的逐接口审查。分页大小、候选全集、源码内容和模型配置保持原有口径。

## 回退与失败处理

- 某页输出无法解析为 JSON，或编号无法核验：保留该页全部证据，避免一次检索失败丢失整页。
- 语义召回无结果或走到允许的提示加载回退路径：调用词面/类别召回。
- 词面召回结合 Claim 词语、接口关联和高风险类别，不设置候选数量上限。
- 模型连接失败会抛出错误，不能当成“没有相关证据”。

## 示例

Claim 写“临时证券代码应依据市场映射处理”，源码使用 Java 标识符。只按中文字面匹配容易漏掉；模型语义召回用于识别相关方法与映射常量。

如果某个长方法的任一片段被选中，后续会按该 EVD 编号取回整个原始证据，而不是只保留命中的片段。

## 当前限制

- 模型可能给出格式合法、语义却漏选的编号；当前未必能自动发现。
- 分页调用之间没有完整的共同推理上下文；内容完整不等于跨页关系被完整理解。
- 后备词面召回仍可能受中文需求与代码命名差异影响。
- 这一步处理初始证据，尚未包含步骤 05 才补入的所有 DTO/响应类。
