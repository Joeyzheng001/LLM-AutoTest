# 11 模型传输、续接与留痕

[返回目录](README.md) · [交接执行说明](10-generation-execution-and-report.md)

## 目的与分工

记录各步骤如何组织模型输入、获取完整返回及追溯调用，区分“程序没有裁掉内容”和“模型已经理解全部逻辑”。由公共模型客户端及各节点的分页代码共同实现。

## 输入与输出

输入：任务合成后的模型配置、步骤名、提示词、业务输入及可选重试设置。

输出：正常结束并完成拼接的模型正文、调用编号及可用的 usage；同时保存载荷和调用元数据。无法完成时抛出错误并记录失败状态。

## 模型选择

生产调用使用任务配置和服务级配置合成的客户端设置。公司模型不是由 Code Review 函数硬编码；当前历史验证任务明确指定公司 `deepseek-chat`。

程序校验、引用归一和确定性汇总不会调用另一个模型代替公司模型生成业务结论。模型身份及参数可从调用记录核对。

## 输入组织

| 调用 | 当前组织方式 |
| --- | --- |
| Claim 证据召回 | 长证据连续拆片，约 8,000 字符/片；目录约 12,000 序列化字符/页 |
| Claim 符合性审查 | 一 Claim、一接口、证据分页；约 4,000 字符/片、8,000 序列化字符/页 |
| 接口测试设计 | 按接口传入其可用证据、分支及 Claim；当前未统一按 token 预算继续分页 |
| 候选修复/正常入口/单分支补查 | 保留该接口的原始输入，并附目标及错误信息 |
| 变更影响分析 | 发送程序整理的变更和关联摘要，不是重新传全仓源码 |

分页预算不包括整个 system prompt、重复的 Claim/接口等所有开销，也不是精确 token 预算。`chunk_json_items` 保持 JSON 实体完整，单个大实体可能独占一页并超过预算。

源码连续拆片保留所有字符；脱敏属于发送前的安全处理，接口字段简表和影响摘要属于明确的数据选择。这些都应与“静默截掉已选输入的尾部”区分说明。

## 有界并行与容量（2026-10-20）

`CODE_REVIEW_MAX_CONCURRENCY` 默认 4，约束单任务 Code Review 的同时活跃 Claim 或接口 worker；每 worker 同一时刻最多发起一次模型调用，召回/审查阶段与接口设计阶段不重叠。`JOB_MAX_CONCURRENCY` 默认 2，因此同进程两个 Code Review 最多合计 8 路；不是跨进程的全局限流器。网关限额较小时可调低该设置，HTTP 429 仍走现有 Retry-After/重试策略，不能靠删源码、换模型或缩短输出实现提速。

并行只改变独立任务的等待安排，不改变原始 system/user、分页、输出上限、续接和修复规则。客户端在首次 await 前分配 call_id，留痕按完成顺序追加，不保证按编号排列。重启按已记录的最大调用序号接续，避免取消留下序号空洞后复用编号；完整载荷仍使用独立临时文件名保存。中途取消的调用可能没有完成留痕，不可当成成功输出。

## 输出获取

1. 按任务协议和输出上限发送请求。
2. 对网络等可重试错误，按客户端策略重试。
3. 返回标记为 length/max_tokens 等上限结束时，将当前输出并入累计正文，携带已有输出继续请求。
4. 拼接时处理重复前缀/重叠内容，直到获得可确认的正常结束标记。
5. 没有新增内容或结束标记不完整时，报错，不作为正常完整回答交给下游。
6. 完整返回后先留痕，再移除受支持的思考块，交给业务解析器。

这是“分批输入与输出续接”的机制，不等于任何模型和网关都能保证在任意上下文长度下不失败。接口设计输入仍可能超过模型可接受范围；当前还没有全流程精确 token 预算和上下文容量协商机制。

## 调用记录

任务目录中的 `llm_calls.jsonl` 记录：

- run_id、call_id、步骤和提示词版本。
- 模型、协议、采样参数。
- 输入/输出字符数和摘要。
- 完整载荷文件路径。
- finish_reason、续接轮数、耗时、usage（提供时）。
- 成功状态及失败错误码。

`llm_payloads/` 保存传入 system/user 及客户端最终得到的输出。正常续接成功时，保存的是合并后的输出，不是每一个网络响应包各自独立的副本。

连接失败时可能没有输出；若续接中途失败，当前失败留痕不保证保存所有已收到的中间片段。因此摘要一致只能证明“已保存的内容与记录一致”，不能证明失败调用也已完整完成。

## 修复调用与网络故障

- JSON/契约修复使用相同任务客户端，再传原始业务输入及校验错误。
- 核心 Claim/测试设计模型连接失败，不能当成无相关源码或无可测分支。
- 可选变更影响分析允许回退程序视图；与核心审查的失败规则不同。
- Code Review 不会因为公司模型不可达，就自动换成其他模型完成业务审查。

## 审计方法与限制

可按 run_id 汇总模型身份、失败次数、结束标记及续接轮数；读取载荷重新计算输入/输出长度与摘要，并核对缺少输出的失败记录。

内容未裁剪、记录完整、引用存在、逻辑正确是不同层面。还需要分别检查跨页语义、接口调用链完整性、分支是否漏设计，以及真实环境执行结果。

例如某次返回因长度限制续接两轮，最终正常结束，可审计合并后的正文、摘要和续接轮数；若第二轮连接失败，就不能把第一轮已有部分内容宣称为完整业务结论。
