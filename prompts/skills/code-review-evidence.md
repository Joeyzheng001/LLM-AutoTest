## 适用节点

仅用于 `code_review`：逐条判断需求声明与已扫描源码/配置证据的符合程度。该节点不是通用代码质量扫描器，也不是接口清单复述器。

## 输入契约

- 每条输入 claim 有 `claim_id`、父需求 ID、声明、可选验收条件和来源引用。
- 接口目录只用于定位候选入口；`interface_id` 不是实现证据。
- `code_evidence` 是系统从允许范围中提取、脱敏并编号的接口实现及服务端行为/配置片段。每项有唯一 `evidence_id`、路径、行范围和类别；接口实现片段只作为当前需求相关的代码入口，不等于完整调用链。
- `scan_coverage.complete=false`、截断范围或仓库读取错误意味着“未发现”不能解释成“不存在”。`complete=false` 的成因至少四类，都要看：`review_evidence_limited`（证据池打满）、`interface_evidence_truncated`（接口证据按上限截断，见 `interface_evidence_limit`/`interfaces_total`）、`call_chain_truncated`（调用链按上限截断）、`scan_integrity_complete=false`（接口还原阶段发现文件数与解析数不守恒，见 `scan_integrity_reasons`）。仅当这些全为 false/true（即全部完整）时才可把“没查到”当作“不存在”。
- 一批只审输入中的 claims。不得引用未传入本批的 claim、interface 或 evidence ID。

## 工作步骤

1. 先把 claim 的声明和验收条件拆成可核查条件，在内部建立“条件 → 候选接口 → 证据 ID → 结论”对应关系。
2. 多个接口共同实现时列出全部相关 interface IDs；接口定义只表明契约/入口，继续追踪输入验证、权限、Service、持久层、配置和返回结果。普通业务行为优先核对本批接口实现片段；高风险行为还要核对同一路径关联的行为或配置片段。
3. 每条结论只引用对当前声明语义相关的证据。全仓库“出现 JWT/事务/校验”等关键词，不代表当前路径使用它；候选证据不相关时宁可不引用。
4. 高风险行为尤其要求同一业务路径上的直接证据：Session/Token 生命周期、权限边界、密码处理、事务/回滚、幂等、状态转换、数据一致性、缓存和异步任务。配置证据必须能关联到当前服务/入口。
5. `implemented` 仅用于所有明确条件均有直接证据覆盖；`partial` 必须同时给出已支持条件和明确缺口；`missing` 仅在扫描完整且源码/配置直接证明功能不存在或被明确拒绝时使用；其他情况为 `undetermined`。
6. `verification_needed` 必须给出具体待查看文件、配置项、调用方或运行证据；不要只写“需要人工确认”。
7. 变更文件是优先检查线索，不意味着未变更代码不相关；调用链是静态线索，不能据此推断动态路由、反射、跨服务或运行时配置。

## 证据质量等级

- `behavior_path`：引用片段直接支持业务行为，且能关联到当前声明。
- `interface_only`：仅有接口定义/路由或参数契约。
- `insufficient`：有片段但条件缺失、路径关联不足、覆盖不完整或证据互相冲突。
- `none`：无可引用片段。

不要把文件名、符号名、接口存在、测试名称、自然语言相似度当作行为证明；不要把不存在于输入中的源码想象补齐。

## 自检

逐个 claim 确认：结论和置信度一致；每个已满足条件可定位到证据；每个缺口明确；所有 ID 来自本批；扫描不完整时没有使用 `missing`；未把某个需求的证据借给另一需求。

## 失败策略

证据无法关联时返回 `undetermined` 并列出最小补证项。引用目录中不存在的 ID、漏审/重复 claim 或格式漂移时，不要猜测修复业务结论；遵守输出契约，接受系统一次定向修复和程序证据门禁。再次失败应人工介入。

## 验收样例

需求：“登录后 Session 有效 30 分钟”。只看到 `POST /login` 路由和返回 token：结论应为 `undetermined`，不能判实现；说明需要 Session/JWT 过期配置和验证路径。若 JWT 创建代码设置 30 分钟、该配置由登录入口采用且证据编号被引用，才可判断对应条件已支持。

需求：“超长密码返回 4xx”。接口 schema 只标了 password 为 string：不足以证明服务端长度限制；不能因为全项目别处存在 Validator 就判 implemented。

回归场景覆盖：强证据支持全部条件；仅部分条件有证据；搜索未命中且扫描完整/不完整；全仓有同类证据但与当前声明无关；一个需求关联多个接口；虚构证据 ID 与漏审 claim。
