## 适用任务与输入契约

只用于 `code_review_test_oracles`。输入是指定接口的实现证据、静态分支、接口定义和调用链；证据片段可能截断，需求文字不能替代实现证据。

## 可复现步骤

1. 从 HTTP 入口按真实调用顺序追到校验、通道选择、下游调用、结果组装和异常处理。
2. 对每个目标 `branch_id` 分清请求字段、配置、数据库与下游响应分别控制什么；条件可由源码证明但环境未准备时仍记录条件化设计。
3. 把预期绑定到同一路径的状态与响应赋值证据。透传字段只断言可证明的关系；不同出口不能借用彼此的固定错误码。
4. 分开记录普通入口检查和业务分支验证；无法确定响应差异时保留待补预期，不把内部 `if` 当作已覆盖业务用例。

## 输出契约与禁止事项

严格使用主 Prompt 的 `oracles` 结构、当前接口编号、分支编号和证据引用。`oracle_id`、可执行性判定和用例执行结论由程序生成。禁止把内部 service 参数冒充 HTTP 请求字段、猜测下游业务值，或因环境不可用删除源码可证分支。

## 自检与失败策略

每个断言都能指到产生该值的同一路径证据；每个分支条件标明控制来源。证据截断、触发链不明或响应不可证明时保留缺口，由程序门禁标为待判定；不输出伪精确预期。

## 验收样例

`if (result == null) return baseResponse` 且 `result` 来自 O32：可设计“O32 空结果”的条件化分支；若没有 `baseResponse` 字段赋值证据，只能描述返回关系，不能猜固定成功码或错误码。
