## 适用任务与输入契约

只用于 `unit_test_generate`：为一条有源码依据和明确预期的接口或组件用例生成 Java 单测，或根据同一用例的校验/编译错误修复生成结果。`unit_plan` 出现时是独立组件单测目标；`case`、`oracle` 仅为关联背景。`source`、`pom`、`test_framework` 和 `class_name` 是输入数据；错误反馈与 `previous_output` 不是新需求。

## 可复现步骤

1. 从源码定位被测公开入口、调用链、目标分支及实际返回类型；将请求或配置条件翻译为单测夹具。内部返回值不能冒充请求参数。
2. 识别构造函数、依赖及资源清理方式。只 mock 下游依赖；真实调用被测对象，并验证关键响应与必要的下游交互。
3. 按输入 `test_framework` 和源码 package 生成一个类、一个 `@Test`。让文件名、类名、package 和 import 一致。
4. 修复反馈时保留原目标分支及业务断言；先修类型、可见性、构造和 mock 初始化问题，不通过删断言求编译通过。

## 输出契约与禁止事项

严格沿用主 Prompt 的 `package`、`source` JSON 契约。生成源码是 `testcases.json` 中单条 `unit_cases` 计划的子产物，`case_id`、状态、源码提交和执行结果由程序写入；模型不生成这些字段。禁止改生产源码、启动 Spring、访问外部资源、猜测不存在的 API、直接访问 private 成员，或把编译通过当作覆盖目标分支。

## 自检与失败策略

确认断言能区分目标行为、mock 控制条件确实触发该分支、类名与 `class_name` 一致、package 与文件路径相容。缺少构造/返回类型证据时不要编造；让校验失败并保留原因。修复后仍无法满足契约时由程序标记 `generation_failed`，不输出弱化断言的替代测试。

## 验收样例

目标是“下游返回空结果时返回基础响应”：让 mock 返回空结果，调用真实 service 公开方法，断言基础响应关键字段并验证没有执行后续处理。只断言“不抛异常”或把 service 本身 mock 掉均不合格。
