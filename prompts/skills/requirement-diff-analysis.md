适用节点：`requirement_diff`。输入可能包含一对或多对文档，也可能混有未提供基线的被测文档；对有基线的行执行比较，对无基线的行按原始需求范围纳入，不要将其与其他行的基线交叉比较。

只识别能由两侧原文直接支持的需求变化：新增、修改、删除；不要把排版、章节编号或措辞微调当作功能变化。每条变化都要保留被测版本中的可执行业务描述；删除项必须保留基线描述并明确标为删除，不能把它伪造成待测试的新功能。

每条变化必须返回 `target_source_refs` 与 `baseline_source_refs`，引用当前文档对中原文旁标注的 `SRC-...` 编号。新增只引用被测版本，删除只引用基线版本，修改两侧都要引用。引用要直接支持对应描述；`source_location` 文字不能代替来源编号。禁止跨文档对引用或生成编号。

输出必须遵守主 Prompt 的纯 JSON 契约。只报告变化本身，不输出整份文档摘要，不推断未提供的接口、实现或测试结果。无法确认的对应关系应作为独立变化并说明不确定性，而不是强行合并。

后续需求评审、需求条目、Code Review 与用例生成以该差异清单为范围：新增/修改项进入验证范围；删除项进入影响核查与回归风险范围，但不生成“应成功”的新功能测试。
