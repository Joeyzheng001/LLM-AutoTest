## 适用范围

适用于需求差异、需求评审、需求条目、接口还原、Code Review、接口用例和 E2E
用例等所有由模型产生 JSON 产物的节点。主 Prompt 与 JSON Schema 是唯一字段契约；
本 Skill 只补充稳定输出方法，不能改变节点业务语义。

## 输出纪律

1. 只输出一个 JSON 对象：不得加解释、思考过程、Markdown 围栏、统计信息或展示层包装。
2. 顶层键、嵌套层级、字段名、数组/对象类型、枚举和值域严格以主 Prompt 为准；不确定时
   使用已定义的待澄清/说明字段，不新造中文别名、`note`、`analysis` 或 `*_error` 键。
3. 系统字段（`schema_version`、`job_id`、来源文件、运行状态）由编排器注入，模型不得输出或
   覆盖它们。
4. 每个数组元素都只基于当前批次可见证据；长文档按批输出本批实体，禁止为补全上下文伪造条目。
5. 定位字段遵守类型：`source_location.line` 只能是大于 0 的整数行号；章节号、功能编号、
   表格坐标（如 `FS-EP2-6`）属于 `source_location.section`，未知行号则省略 `line`。

## 输出前自检

- 对照主 Prompt 逐项检查必填字段；确保顶层只有 Schema 允许的键。
- 检查容器名是否为节点规定名（例如 `items`、`changes`、`mappings`、`cases`），不要改成
  `data`、`result`、`output` 或自然语言名称。
- 检查列表元素类型。例如测试特性要求字符串时，不得输出脑图/树形对象；用例步骤要求
  selector 时，不得用空值占位。
- 固定维度、状态和严重性必须使用契约原词；不能以翻译词、同义词或附加理由替代。

## 受控兼容边界

客户端只会处理**可证明无业务歧义**的格式差异：代码围栏、已登记的容器别名、纯数字字符串
行号，以及“章节号被误写到 line 且 section 为空”时迁入 section。客户端不会补造业务内容、
默认评分、缺失的映射/步骤/鉴权信息，也不会猜测未知枚举。缺少必填字段、多个解释都成立、
或会掩盖产品缺陷的输出必须失败并进入人工介入。

## 历史问题准入与更新

发现新漂移时，先在 `memory/model-output-drift.md` 登记：节点、实际结构、Schema 报错、
可证明等价性、允许/拒绝的处置以及回归样例。仅在以下条件同时满足时才新增归一化：

1. 有可复现原始形态和对应 Schema 错误；
2. 转换不改变业务含义且不会丢失必填信息；
3. 已增加单元测试，覆盖正常、归一化和拒绝路径；
4. 在 changelog 记录版本与原因。
