## 适用范围

用于接口/E2E 测试点和用例设计，帮助模型把“可验证的产品行为”与“执行前置/环境失败”分开。
本记忆不替代执行器的 HTTP、参数、鉴权和 Schema 判定；最终分类以程序化结果和原始证据为准。

## 已验证归因规则

1. 缺少接口声明的必填参数、未知 body/query 容器、缺少 selector 或不可加载脚本，属于输入构造/执行前置问题；不能设计成成功路径的断言。
2. 成功路径收到 401/403，优先检查鉴权会话、Token 注入和登录前置；没有独立服务端证据时不得直接判定产品权限 Bug。
3. 连接拒绝、DNS/TLS、浏览器缺少运行时、路由 404/网关 502，以及超时，先归环境失败；只有需求明确要求该错误语义时，才设计对应异常用例。
4. 服务端已收到合法请求、返回可解析响应，且状态码或响应语义与明确预期不符，才进入断言失败；需同时保留请求参数、期望、实际状态和实际响应摘要。
5. HTTP 500 不能仅凭状态码认定产品 Bug：先确认请求参数完整、鉴权有效、前置数据存在，再结合服务端堆栈或重复复现判断。

## 输出纪律

- 每个异常用例都说明触发条件、预期状态/语义和证据来源。
- 不为了凑数量把环境错误改写成产品缺陷，也不把产品行为猜成环境问题。
- 对无法区分的情形标记“需要证据”，给出最小补证建议，不臆造服务端配置。
