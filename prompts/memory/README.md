# 长期记忆准入规则

这里只存放经过程序验证、人工审核或重复复现的经验，不存原始需求、模型原文、API Key、用户名密码或个人信息。

每条记忆必须有版本、规格号、适用节点（由 Prompt loader 映射）、可验证表述和变更记录。
经验被证明失效时应更新或删除；节点调用只加载映射到该节点的少量条目，禁止全库注入。

## 进入长期记忆前的三步

1. 在 `docs/13_问题与需求变更记录.md` 先记录事实、影响、证据和修复状态，并归入“功能与业务 / 用户体验 / 技术质量与稳定性”之一。
2. 只有经过程序测试、人工审核或至少两次可重复复现的规则，才提炼成 memory；一次性的模型原文、猜测和未验证结论留在任务日志，不升级为长期规则。
3. memory 只写“如何判断、允许怎样处理、何时必须拒绝”，不写 API Key、密码、Token、个人信息或具体项目的业务数据；规则变更必须增加 changelog 和回归测试。

## 失效与回滚

规则与当前 Schema、执行器或部署基线冲突时，以代码和正式 Schema 为准；先停用对应映射或回退版本，再补充反例测试，不能通过扩大兼容边界掩盖规则失效。
