## 已验证部署原则

- 数据库保存任务、节点、事件和产物索引；JSON、脚本和报告正文保留在证据卷或对象存储，
  不把大产物塞进关系库。
- 多实例执行必须依赖数据库任务租约、心跳和幂等领取；单机内存状态只能作为开发兼容模式。
- 任务列表与详情应优先读数据库索引，本地 `state.json` 只作为证据补充和旧任务回退；
  共享卷暂时不可见不应让任务消失。
- 备份恢复先恢复到隔离数据库，再核对任务数量、节点状态、产物索引和对象可读性，禁止直接
  覆盖生产库。
- 数据库能连通不等于服务可接任务：必须先执行版本化 `migrate-db`，`/ready` 的 Schema
  版本与当前服务匹配后才算就绪；旧版本数据库应返回迁移所需状态，不静默执行结构变更。
- 启用 S3/MinIO 镜像时，任务接收前必须完成只读 bucket 探活；对象存储不可用应让 `/ready`
  失败并触发部署告警，本地文件模式不应伪造对象存储状态。
- API Key、登录密码、Cookie 和 Git Token 不进入 Prompt、普通任务配置、审计事件或导出包；
  通过 Secret Store/KMS 注入并在日志出口统一脱敏。
- 当前生产模型候选为 MiniMax-M3/M2.7/M2.5，未填写任务级模型时服务级默认必须为
  MiniMax-M3；单次 HTTP 调用默认等待 300 秒（`LLM_TIMEOUT_S` 可调），仍受有限重试、Schema
  校验和批次 checkpoint 约束，不能用无限等待掩盖网关故障。

这些规则是部署与运维验收清单，不是让模型生成业务事实的依据；节点 Prompt 只在需要时引用。
