## 通用原则

结构化输出常见失败是固定字段错层、中文别名、额外诊断字段和展示型对象替代字符串数组。
生成时优先服从当前主 Prompt 的 JSON 契约；不确定内容填入已定义说明字段，绝不新建键或容器。

## 已验证案例

| 节点 | 漂移形态 | 可接受处置 | 禁止处置 |
| --- | --- | --- | --- |
| requirement_review | 评分维度使用既登记中文别名；评审项被错误嵌套；测试特性输出为展示树 | 映射已登记别名、展开叶子字符串；再过 Schema | 补默认总分、评级、summary 或删除未知业务字段 |
| req_parse | `items` 被包进 `data/result/output`，或 `source_location.line` 是纯数字字符串 | 提取已登记容器；数字字符串转正整数 | 从标题猜行号或补写来源 |
| req_parse | 功能/章节编号如 `FS-EP2-6` 误放到 `line` | section 为空时迁入 `section`，移除无效 `line` | 将编号伪造为行号，或覆盖已有 section |
| code_review | 映射数组被包进已登记容器或使用已登记映射别名 | 提取无歧义数组后继续字段校验 | 补造 requirement、代码位置或判定结论 |
| testcase / e2e | 输出缺少 `cases`，或 E2E 步骤缺 selector | 仅修复已登记容器形态 | 为步骤猜 selector、请求参数、预期结果或鉴权 |
| testcase | 模型正文被兼容网关包装为 `{"body":"{...}"}` | 仅解码顶层 `body` 中可解析且仍满足 cases 校验的 JSON；同时以节点专用输出契约约束模型 | 扫描任意业务字段、补造 cases 或将 body 参数当响应包装 |
| testcase | 只有一条用例时直接返回单个对象，顶层字段为 `interface_id/category/title/params/expected`，没有 `cases` | 仅当字段形态完整、`params` 为对象且 `expected` 为非空字符串时，提升为单元素数组；随后仍执行接口归属、场景枚举、参数一致性和批次覆盖校验 | 把任意带 `interface_id` 的对象、`recon_date` 或 `body` 误当用例；用默认值补齐缺失字段 |
| testcase | 只返回当前批次首个接口或只返回 `normal`，导致 `boundary/exception` 或后续接口漏产 | 按“接口 × 场景”计算批次覆盖，修复轮明确列出缺口；修复后仍不齐则阻止残缺产物并保留检查点 | 用已有接口的用例复制到缺失接口、把全局历史用例拼入本批 |
| testcase | 顶层串入 `recon_date`、`pk`、`close_type` 等接口还原/业务字段，或返回 `{}` | 保留顶层形状诊断，交给节点专用修复轮一次；仍失败即人工介入，避免跨节点字段被兼容层吞掉 | 扫描任意嵌套字段找 cases、删除未知字段后强行通过 |

## 新案例记录模板

新增条目必须包含：`节点`、`模型实际输出形态`、`对应 Schema 错误`、`等价性证明`、
`允许的归一化或拒绝原因`、`回归测试文件`。没有这六项，不把偶发问题升级为全局兼容规则。

## 修复轮规则

首次输出被解析或业务校验拒绝时，只允许对同一原始输入发起一轮定向修复；修复提示必须带当前节点的输出契约，明确顶层容器、必填字段、批次覆盖和禁止字段。
修复后仍必须重新解析、业务校验和 Schema 校验；第二次失败直接保留错误上下文并人工介入，不通过无限重试换取“看起来成功”的产物。
