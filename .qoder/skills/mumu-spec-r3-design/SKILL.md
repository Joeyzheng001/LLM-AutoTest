# R3 — 展开（08 + 10 → 06 + 07 + 11）

## 职责

| 文档 | 写什么 |
|------|--------|
| **08** | 组件、部署、技术选型、与外部系统边界 |
| **10** | 表/集合、字段、索引、约束；字段名与 **09** 一致 |
| **06** | 界面状态、交互、异常分支；引用 `05` 的 US/REQ |
| **07** | 性能、可用性、审计等 NFR；可被 `13` 验证 |
| **11** | 认证、授权、威胁与缓解；与 `07` 安全类不重复堆砌 |

## 推荐顺序

1. **`08`** — 定边界与模块划分。  
2. **`10`** — 数据真源（存储侧）；改字段先想是否动 **09**。  
3. **`06`** — 按 US 展开行为细节，不复制 `09` 全文。  
4. **`07`** — 量化指标（延迟、可用率等）。  
5. **`11`** — 安全控制映射到 `09` 鉴权与 `10` 敏感字段。

## 输入

- 已互校准的 **`05`、`09`**。  
- `03` 的 Phase 1 范围（勿在 `06` 扩进 Phase 2）。

## 步骤

1. 读 `01` 铁律：PRD 不写 SQL、API 不写像素。  
2. 打开 `08`～`11`、`06` 样例文件，保持章节标题。  
3. `06` 每条异常路径对应 `05` AC 或注明「见 US-xxx」。  
4. `10` 每个持久化字段能在 `09` DTO/响应中找到或说明内部字段。  
5. 更新各篇变更记录。
