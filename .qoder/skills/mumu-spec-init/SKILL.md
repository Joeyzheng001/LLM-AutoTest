# 初始化 — 新项目骨架创建

## 职责

为新项目创建完整的 `MumuSpec/` 目录（兼容旧路径 `Spec模板/`），包含 01-14 篇文档的骨架文件。
每篇包含：
- 元数据表（模块编号/名称/版本/状态）
- 章节标题结构
- 空变更记录表

## 输入

- **模块编号**：如 `M1`、`PAY`、`ORDER`（用于文件命名前缀）
- **模块名称**：如 `QA平台`、`支付中心`（写入元数据）
- **目标路径**：默认在项目根目录创建 `MumuSpec/`

## 执行步骤

1. **确认参数**：问清模块编号和模块名称，如用户未指定则建议默认值
2. **创建目录**：`MumuSpec/`（若已存在则跳过，兼容 `Spec模板/`）
3. **生成骨架文件**：01-14 各一篇
4. **写入 `01` 总则**：包含写作铁律（PRD不写SQL、API不写像素等）
5. **输出确认信息**

## 01 总则特殊内容

`01` 需额外包含以下铁律：

### 写作铁律

1. **PRD 不写 SQL**：`04` 不出现 CREATE TABLE、SELECT 等语句
2. **API 不写像素**：`09` 不描述 UI 布局、颜色、间距
3. **契约真源**：对外字段以 `09` 为准，存储以 `10` 为准
4. **不混层**：用户故事不写接口细节，接口规格不写用户价值
5. **写作顺序**：R1→R2→R3→R4，不按 01→14 编号顺序硬写

### 编号规则

- REQ 编号：`REQ-[模块ID]-[序号]`，如 `REQ-M1QA-001`
- US 编号：`US-[模块ID]-[序号]`，如 `US-M1QA-001`
- API 编号：`API-[序号]`，如 `API-001`
- TC 编号：`TC-[模块ID]-[序号]`，如 `TC-M01-001`

## 完成后

1. 提示用户：骨架已创建，可以运行 `/mumu-spec-main` 开始编写
2. 推荐从 R1（`/mumu-spec-r1`）开始：整理需求素材
3. 提示运行 `/mumu-spec-status` 可查看整体状态
