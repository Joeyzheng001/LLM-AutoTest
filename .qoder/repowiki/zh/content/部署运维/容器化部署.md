## 项目结构
LLM-AutoTest 采用多服务架构，通过 docker-compose 进行编排：
- java-parser：Java 服务，提供代码解析能力
- orchestrator：Python 服务，负责流水线编排、产物管理与 REST API
- frontend：Nginx + Vue.js 静态页面，提供 Web 界面
- test-executor、mock-services：可选服务，按 profile 启用

## 核心组件
- java-parser：基于 Spring Boot + Maven 的多阶段构建镜像，暴露 8080 端口，提供 /health 健康端点

- frontend：基于 Nginx + Vue.js 的多阶段构建镜像，暴露 80 端口，提供 Web 界面并通过 nginx 反向代理到 orchestrator
- test-executor、mock-services：按需启用的辅助服务

**更新** frontend 服务现已实现完整的 Vue.js 应用构建，使用 pnpm 作为包管理器，通过多阶段构建优化镜像大小。

## 详细组件分析

### java-parser 服务
- 多阶段构建：使用 maven:3.9-eclipse-temurin-21 作为构建阶段，最终镜像仅包含 JRE 运行时
- 暴露端口：8080
- 健康检查：/health 端点，compose 中使用 wget 探测
- 配置：application.yml 中定义 server.port 与 parser.scan-concurrency；支持环境变量覆盖
- 并发控制：scanConcurrency 必须为正数，防止非法配置导致异常

### frontend 服务
- 多阶段构建：第一阶段使用 node:20-alpine 构建 Vue.js 应用，第二阶段使用 nginx:1.27-alpine 提供服务
- 包管理器：pnpm@9.15.0，通过 corepack 启用
- 暴露端口：80
- 反向代理：通过 nginx.conf 将 /api 请求代理到 orchestrator:8000
- 构建优化：使用 --frozen-lockfile 确保依赖一致性，构建产物复制到 nginx 静态目录
- 缓存策略：index.html 不缓存，带 hash 的资源文件可长缓存

## 环境变量与配置管理
- orchestrator 必需环境变量：
  - JAVA_PARSER_URL：指向 java-parser 服务地址（默认 http://java-parser:8080）
  - LLM_BASE_URL、LLM_MODEL_NAME、LLM_API_KEY、LLM_TEMPERATURE、LLM_TOP_P、LLM_SEED、LLM_TIMEOUT_S：LLM 调用相关参数
  - PORT：服务监听端口（默认 8000）
  - ARTIFACTS_ROOT：制品根目录（默认 /data/llm-autotest）
  - SCHEMAS_DIR：Schema 目录（默认 schemas）
- java-parser 配置：
  - server.port：服务端口（默认 8080）
  - parser.scan-concurrency：并发度（必须为正数）
- compose 中通过 environment 与 env_file 注入变量，建议将敏感信息放入 .env 文件并通过 --env-file 传入

**更新** orchestrator 现在支持更多 LLM 配置选项，包括模型名称、温度、Top-P 等参数。

## 构建与镜像优化策略
- java-parser：
  - 多阶段构建：构建阶段使用 Maven，运行阶段仅包含 JRE，减小镜像体积
  - 依赖缓存：利用 Docker 层缓存加速构建
- orchestrator：
  - 使用 uv 进行依赖管理，分步安装减少镜像层大小
  - 冻结依赖：uv sync --frozen 确保构建可重复
  - 预装 Chromium：支持端到端测试功能
- frontend：
  - 多阶段构建：构建阶段使用 Node.js，运行阶段使用轻量级 Nginx
  - 依赖缓存：使用 pnpm 和 --frozen-lockfile 优化依赖安装
  - 资源优化：构建产物最小化，静态资源带 hash 支持长缓存
- CI 集成：
  - GitHub Actions 对 Python、Java、Frontend 分别执行 lint、build、test
  - 推送 main 分支时触发 Docker 构建

**更新** frontend 服务现在实现了完整的多阶段构建流程，显著减少了镜像大小并提高了构建效率。

## 开发与生产环境差异
- 端口映射：
  - 开发：java-parser:8081->8080, orchestrator:8000->8000, frontend:8080->80
  - 生产：建议通过反向代理（如 Nginx/Traefik）统一管理入口，避免直接暴露内部端口
- 网络配置：
  - 开发：默认 Docker 网络即可
  - 生产：建议使用自定义网络隔离，限制服务间访问权限
- 存储策略：
  - 开发：本地卷或临时卷
  - 生产：建议使用云盘或对象存储，结合备份与监控
- 环境变量：
  - 开发：可使用默认值或本地 .env
  - 生产：通过密钥管理服务注入敏感变量
- 反向代理：
  - 开发：可直接访问各服务端口
  - 生产：通过 nginx 统一入口，提供 SSL 终止、负载均衡等功能

**更新** 生产环境推荐使用 nginx 作为统一入口，提供更好的安全性和性能。

## 常见问题排查
- java-parser 启动失败：
  - 检查 /health 端点是否可达
  - 确认 parser.scan-concurrency 是否为正数
  - 查看 JVM 内存配置是否正确
- orchestrator 无法连接 java-parser：
  - 确认 JAVA_PARSER_URL 是否正确
  - 检查网络连通性与防火墙设置
  - 验证服务间的 DNS 解析
- 前端无法访问：
  - 确认 frontend 服务已启动且端口映射正确
  - 检查 nginx 反向代理配置
  - 查看浏览器控制台是否有跨域或网络错误
- 制品丢失：
  - 检查 volumes:artifacts 是否挂载成功
  - 确认容器内路径 /data/llm-autotest 是否存在
  - 验证被测仓库挂载路径 /opt/repos 是否可读
- 构建失败：
  - 检查依赖安装是否成功
  - 确认 pnpm 和 uv 版本兼容性
  - 查看构建日志中的具体错误信息

**更新** 新增了前端相关的故障排查指南，包括 nginx 反向代理问题的诊断方法。
