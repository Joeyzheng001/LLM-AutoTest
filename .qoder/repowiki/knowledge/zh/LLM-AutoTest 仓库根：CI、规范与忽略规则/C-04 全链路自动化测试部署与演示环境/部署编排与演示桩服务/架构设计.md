本模块由四个相互独立的部署工件组成，共同构成演示/联调环境的运行时：
- `deploy/llm-stub/stub_server.py`：基于 Python 标准库 `http.server.ThreadingHTTPServer` 实现的 OpenAI `/chat/completions` 兼容桩，按 system prompt 中的 JSON 键（`items`/`interfaces`/`mappings`/`cases`）路由到需求解析、接口重构、CodeReview 映射、用例生成四个语义节点，并在无法解析时回落到内置的 5 条 demo 需求；对外暴露 `choices`+`usage` 结构以替换真实 GLM 网关。
- `deploy/task-config/demo.repos.json`：声明式仓库清单，列出 `user-service` 与 `order-center` 两个演示仓库的路径与分支，被 orchestrator 读取用于代码扫描。
- `deploy/docker-compose.yml`：编排 `java-parser`、`orchestrator`、`frontend` 三个核心服务及可选的 `test-executor`/`mock-services`（通过 profiles 启用），共享 `artifacts` 卷并设置健康检查与依赖顺序；通过 `.env` 注入 LLM_BASE_URL 等环境变量。
- `deploy/nginx.conf`：Nginx 反代配置，将 `/api/` 转发至 `orchestrator:8000`，静态资源走 `/usr/share/nginx/html`，并对 `/index.html` 禁用缓存、对带 hash 的 assets 长缓存。
依赖方向：nginx → orchestrator → java-parser；llm-stub 作为独立进程被外部通过环境变量指向，不参与 compose 网络。
