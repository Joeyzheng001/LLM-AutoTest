该模块为纯数据/文档目录，按 job_id 划分独立子目录（如 `job-demo-defect-0004`、`job-web-c3e382183000-demo`），每个子目录是一次运行任务的不可变产物快照。核心 JSON 文件构成固定契约：`state.json` 记录节点流水线状态（req_parse → code_scan → interface_reconstruct → code_review → testcase_generate → auto_execute → test_report → defect_list → retest_regression）；`execution.json` 以 case_id/interface_id 维度输出单条用例通过/失败（区分 assertion/environment 两类 failure_kind）；`defects.json`、`requirement_items.json`、`code_inventory.json`、`interfaces.json`、`interface_candidates.json`、`review_mapping.json`、`metrics.json`、`regression_index.json`、`llm_calls.jsonl` 分别承载缺陷、需求项、源码清单、接口定义、LLM 调用轨迹等中间产物；`testcases.json`、`test_report.md` 提供用例与报告；`scripts/` 下保留可复现的回归脚本（如 `regression/rest/test_TC_009.py`）。README.md 说明复现命令、环境依赖与 G1–G5 判定对照，作为该证据物的元说明。两个示例分别代表“桩 LLM + 真实被测服务”的缺陷闭环 Demo 与“脱敏的真实 MiniMax 运行”快照，二者共享同一套产物 schema。
