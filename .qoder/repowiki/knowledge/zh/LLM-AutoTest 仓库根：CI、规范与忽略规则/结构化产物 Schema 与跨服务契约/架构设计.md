模块以扁平的 JSON Schema 文件为根（requirement_items/code_inventory/interface_candidates/interfaces/review_mapping/testcases/execution/defects/regression_index/metrics.json），每个文件对应 docs/11 §5.3 主笔表中的一项产物，并通过 `schema_version` 字段实现向后兼容的版本控制；`contracts/java-parser.openapi.yaml` 是首个跨服务契约，定义 java-parser 服务的健康检查、扫描任务（scan-jobs）与接口候选提取任务（extract-jobs）的异步 job 模式，其内部组件 schema（RepositoryInput、SourceFile、InterfaceCandidate 等）与顶层 JSON Schema 中的 code_inventory.json、interface_candidates.json 一一对应；`samples/` 提供带 `_fake: true` 标注的演示样例，禁止进入正式流程。依赖方向单向：orchestrator / test-executor 通过 pydantic 模型消费这些 Schema，java-parser 通过 OpenAPI 生成客户端代码，三者均以本目录为权威来源。
