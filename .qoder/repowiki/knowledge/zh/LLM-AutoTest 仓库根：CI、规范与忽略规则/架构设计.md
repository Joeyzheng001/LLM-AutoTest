根目录不承载业务逻辑，而是作为多服务仓库的横切治理层：
- `.github/workflows/ci.yml` 以矩阵方式并行执行 Python（orchestrator/test-executor）、Java（java-parser）与 Frontend 三套流水线，并在 push 到 main 时触发 Docker 镜像构建，将各子服务产物纳入统一镜像命名空间 `llm-autotest/<service>:ci`。
- `.rules/` 集中定义前端、Java、Python 的代码风格与 LLM 完整性检查规则，被对应子服务的 lint/mypy/ruff 等工具链引用，形成跨语言的统一质量门禁。
- `.gitignore` 在仓库级屏蔽 Python/Java/Node 构建产物、运行时数据目录 `/data`、`volumes/` 及敏感凭据，同时显式放行 `deploy/.env.example` 与 `uv.lock`，确保多语言子模块共享一致的提交边界。
- 三个子模块（docs_and_specs、schemas、deploy）通过 schemas 提供的 JSON Schema/OpenAPI 契约与 deploy 的 Compose 编排耦合，由本根的 CI 与 .gitignore 共同约束其演进路径。
