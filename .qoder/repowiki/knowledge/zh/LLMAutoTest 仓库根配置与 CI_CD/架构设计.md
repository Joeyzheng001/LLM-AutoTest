本层不承载业务逻辑，而是作为跨子模块的统一治理入口：
- `.github/workflows/ci.yml` 通过 matrix 并行执行 Python（orchestrator/test-executor）、Java（java-parser）与 Frontend 的 lint/format/typecheck/build 任务，并在 push 时触发 Docker 镜像构建，将各子服务纳入同一份 CI 契约。
- `.rules/` 提供按语言划分的代码风格规范（ruff/mypy、maven 插件、前端 ESLint/Prettier），被对应子服务的构建步骤引用，形成跨语言的统一质量基线。
- `.gitignore` 在仓库级屏蔽各语言运行时产物（.venv、target、node_modules、/data、volumes）与环境密钥，同时显式保留 uv.lock 与 deploy/.env.example，保证依赖锁定与环境模板在多服务间一致可见。
- `schemas` 与 `docs_and_specs` 作为跨子模块共享的事实源，由 CI 中各服务的测试/校验步骤间接消费，从而把需求规格、JSON Schema、OpenAPI 契约与代码实现串联起来。
