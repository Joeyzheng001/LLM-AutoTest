## 三、关键交互规则摘要

- R-ORCH-01：上游节点产物未生成时，下游节点拒绝启动并报错
- R-ORCH-02：各节点间以文件为接口（结构化 JSON 落盘到固定目录）
- R-REQ-02：条目 ID 全局唯一、跨格式稳定
- R-REV-02：还原策略 = 先静态特征定位再 LLM 语义解析
- R-REVW-02：遗漏功能清单由程序从映射表过滤"未实现"生成
- R-GEN-02：生成后执行程序化校验：参数名 ⊆ 接口定义参数集合
- R-EXEC-01：执行引擎按协议路由到对应 Runner
- R-RPT-02：报告数值由 execution.json 程序化汇总，不经 LLM
- R-DEF-01：仅"断言失败"用例进缺陷清单
- R-REG-01：归档 = 移动（非复制）复测通过的脚本至回归目录
- R-MTR-01：9 节点固定口径

## 四、关键边界与异常分支摘要

- X-ORCH-01：某节点失败 → 停止后续节点，输出失败节点 + 原因
- X-REQ-01：文件不存在 → 明确报错退出（退出码非 0，stderr 含 `[REQ-ERROR]`）
- X-REV-03：LLM 输出不符合 Schema → 重试 1 次；仍失败则丢弃该接口
- X-REVW-01：需求条目找不到任何相关代码 → 标"未实现"
- X-GEN-02：参数一致性校验连续 2 次不通过 → 该接口用例放弃
- X-EXEC-01：被测服务不可达 → 该协议用例标记"环境失败"
- X-RPT-01：execution.json 缺失 → 报告生成失败并报错
- X-DEF-01：复测时被测代码已变更 → 复测结果标注"基于新版本"
- X-REG-02：回归重跑结果与沉淀时不一致 → 报告中标"回归漂移"
- X-MTR-01：某节点被降级跳过 → 按"人工介入"计入（分母固定为 9）
