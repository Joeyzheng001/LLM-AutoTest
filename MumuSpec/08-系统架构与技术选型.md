## 一、总体架构

系统整体容器化，按职责拆分为多个 Docker 容器：

```
┌─────────────┐   ┌──────────────────┐   ┌──────────────┐
│  frontend   │──▶│  orchestrator    │──▶│ java-parser  │
│ Vue + Nginx │   │ (Python 流水线)   │   │ (Java 解析)   │
└─────────────┘   └───────┬──────────┘   └──────────────┘
                          │ ▼
              ┌───────────┴───────────┐
              │  test-executor (Python) │──▶ mock-services (多协议)
              └───────────┬───────────┘
                          │
                     GLM-5.3 API（外部）
```

## 二、容器清单

| 容器 | 技术栈 | 职责 | 对应规格 |
|------|--------|------|----------|
| frontend | Vue 3 + Vite + Nginx | 任务配置、流水线监控、三视图展示、报告/缺陷/度量查看 | 07 全部 6 页方向 |
| orchestrator | Python 3.11 + FastAPI | 9 节点编排、断点续跑、产物管理、REST API | 模块 0（F-ORCH-01/02） |
| java-parser | Java 21 + Spring Boot 3 + JavaParser | Java 多仓库扫描与接口逆向还原 | 模块 2 / 3（G3、R2） |
| test-executor | Python 3.11 + pytest | 测试脚本加载与无人值守执行、断言二态判定 | 模块 6（E-TEST-02） |
| mock-services | 按协议 | gRPC / GraphQL / SOAP / MQ 的 Mock 执行环境 | F-EXEC-06、R3 降级策略 |

## 三、技术栈选型

| # | 层次 | 技术 | 选型理由 |
|---|------|------|----------|
| 1 | 流水线主体 / 后端服务 | Python 3.11 | 全链路生态最全：三格式文档解析、GLM-5.3 SDK、测试执行引擎、报告与度量汇总 |
| 2 | Java 接口逆向解析 | Java 21（独立服务） | 被测系统为 Java 多仓库，Java 生态的源码解析工具最成熟 |
| 3 | 前端 | Vue 3 + Vite | 系统部署在 Linux 服务器上供团队使用，需要操作与查看界面 |
| 4 | LLM | GLM-5.3 | 冻结基线技术基线，不新增模型投入 |
| 5 | 测试框架 | pytest | 生成脚本的语法目标与执行引擎载体 |
| 6 | 部署 | Docker + docker-compose | 多容器化部署，独立升级、独立扩缩、故障隔离 |

## 四、混合架构原则

Python 为流水线主体，Java 解析以独立服务形式嵌入（Python ↔ Java 通过 REST API 交互，而非进程内混合），边界即模块 2/3 与其余模块的规格边界。

## 五、部署方案

- **目标环境**：Linux 服务器，供团队多人使用
- **部署形态**：多 Docker 容器化部署
- **交互入口**：
  1. 团队日常使用：Vue 前端界面（Web）
  2. 基线口径兼容：orchestrator 容器内保留统一入口命令
- **产物与状态**：结构化产物通过挂载卷持久化，容器内挂载点统一 `/data/llm-autotest`

## 六、与外部系统边界

| 外部系统 | 交互方式 | 说明 |
|----------|----------|------|
| GLM-5.3 API | HTTPS REST | LLM 推理调用，唯一允许的 LLM 后端 |
| Java 多仓库 | 本地文件系统 | 代码扫描与接口解析的输入源 |
| 需求文档 | 本地文件系统 | Word / Markdown / Excel 三格式输入 |

## 七、关键设计决策

| 决策 | 理由 | 影响 |
|------|------|------|
| Python 主体 + Java 解析服务分离 | 被测系统为 Java，同栈解析能力最强 | 服务间通过 REST API 交互 |
| GLM-5.3 冻结基线 | 公司现有资源，不新增投入 | 禁止引入其他模型 |
| pytest 测试框架 | 生态成熟，团队熟悉 | 生成脚本语法目标 |
| docker-compose 编排 | 一周周期内最轻量方案 | 容器边界可调整 |
| Vue 前端 | 团队可用完整 Web 界面 | 06 V2.1 裁决批准 |
