## 一、用户故事清单

### Epic 1：需求输入通道（E-REQ）

#### US-M1AT-001 需求文档多格式解析

> **作为** 测试专项小组成员，**我希望** 系统能自动解析 Word / Markdown / Excel 三种格式的需求文档并抽取结构化需求条目，**以便** 后续 Code Review 与用例生成环节可以直接消费标准化输入。

**验收标准（AC）**：
- AC1：给定 1 份 Word 格式需求样例文档，解析产出结构化需求条目 JSON，条目数与预置 golden 期望条目数一致
- AC2：给定 1 份 Markdown 格式需求样例文档，解析产出同构 JSON，通过同一 Schema 校验
- AC3：给定 1 份 Excel 格式需求样例文档，解析产出同构 JSON，通过同一 Schema 校验
- AC4：对格式不符或空文档输入，给出明确错误提示而非静默失败（退出码非 0，stderr 含 `[REQ-ERROR]`）

**优先级**：P0 | **对应 REQ**：REQ-M1AT-001

---

### Epic 2：代码输入通道（E-CODE）

#### US-M1AT-002 Java 多仓库代码扫描

> **作为** 测试专项小组成员，**我希望** 系统能扫描指定的多个 Java 仓库（≥2 个）并汇总可分析的源码清单，**以便** 后续接口逆向解析有统一的代码输入。

**验收标准（AC）**：
- AC1：对 2 个指定 Java 仓库执行扫描，输出含仓库、模块、源码文件路径的结构化清单
- AC2：扫描过程无人工操作（只需启动命令时指定仓库路径）
- AC3：对不存在的仓库路径给出明确错误提示

**优先级**：P0 | **对应 REQ**：REQ-M1AT-002

#### US-M1AT-003 LLM 接口逆向还原

> **作为** 测试专项小组成员，**我希望** LLM 能从 Java 源码中逆向还原接口定义（路径、方法、入参、出参、协议类型），**以便** 在无接口文档的前提下获得接口结构化清单作为唯一接口来源。

**验收标准（AC）**：
- AC1：对演示仓库中至少 5 个接口（含 REST 与至少 1 种非 REST 协议），还原出结构化接口定义，路径/方法/参数名与源码一致
- AC2：还原产物为结构化 JSON，通过预定义 Schema 校验
- AC3：对无法解析的文件输出"跳过 + 原因"记录，不中断整体流程

**优先级**：P0 | **对应 REQ**：REQ-M1AT-003

---

### Epic 3：Code Review 环节（E-REVIEW）

#### US-M1AT-004 需求-代码映射表生成

> **作为** 测试专项小组成员，**我希望** 系统能逐条比对需求条目与还原的接口/代码实现，产出需求-代码映射表，**以便** 它作为上游产物派生风险清单与遗漏功能清单。

**验收标准（AC）**：
- AC1：映射表覆盖输入需求条目的 100%，每条需求标注"已实现 / 部分实现 / 未实现 / 无法判断"四态之一
- AC2：每条"已实现"条目附带对应代码位置（仓库 + 文件 + 方法名）
- AC3：映射表为结构化产物（JSON/MD），可被下游程序消费

**优先级**：P0 | **对应 REQ**：REQ-M1AT-004

#### US-M1AT-005 风险清单与遗漏功能清单生成

> **作为** 测试专项小组成员，**我希望** 基于映射表自动派生风险清单和遗漏功能清单两种视图，**以便** 测试团队直接获得评审结论性产物。

**验收标准（AC）**：
- AC1：风险清单中每项风险包含"风险描述 + 对应需求条目 + 代码位置"三要素
- AC2：遗漏功能清单与映射表中"未实现"条目 100% 一致（可程序校验）
- AC3：三种产物（映射表/风险清单/遗漏清单）一次生成、三种视图输出

**优先级**：P1 | **对应 REQ**：REQ-M1AT-005

#### US-M1AT-006 LLM 产物人工审核

> **作为** 测试专项小组成员（人工审核角色），**我希望** 对 LLM 关键产物进行人工审核并记录结论，**以便** 被驳回的产物有明确回流路径。

**验收标准（AC）**：
- AC1：审核对象至少覆盖接口还原与映射表两类关键产物，每类给出"通过 / 驳回"结论
- AC2：驳回结论必须附驳回原因，审核记录以结构化文件落盘
- AC3：被驳回的产物标记"待修正"，完成至少 1 次完整"驳回 → 修正 → 复审"闭环

**优先级**：P1 | **对应 REQ**：REQ-M1AT-006

### Epic 4：用例生成与执行（E-TEST）

#### US-M1AT-007 LLM 测试用例生成

> **作为** 测试专项小组成员，**我希望** LLM 基于还原的接口定义和需求条目自动生成可执行测试脚本，**以便** 无需人工从零编写接口测试脚本。

**验收标准（AC）**：
- AC1：对至少 5 个已还原接口，每接口生成 ≥3 条用例（正常/边界/异常各 ≥1）
- AC2：生成的用例参数结构与接口还原定义一致
- AC3：生成的脚本在选定的测试框架下语法合法

**优先级**：P0 | **对应 REQ**：REQ-M1AT-007

#### US-M1AT-008 测试框架选型与执行引擎

> **作为** 测试专项小组成员，**我希望** 选定一套测试框架并搭建执行引擎，**以便** 生成的测试脚本可以无人值守自动执行。

**验收标准（AC）**：
- AC1：产出选型说明文档，含 ≥2 个候选框架的对比和选定理由
- AC2：一条命令触发全量用例执行，执行过程无人工操作
- AC3：需鉴权/前置数据的被测接口，前置数据在流程启动前预置于执行配置
- AC4：执行结果以结构化形式输出（每用例：通过/失败 + 失败原因）

**优先级**：P0 | **对应 REQ**：REQ-M1AT-008

#### US-M1AT-009 多协议执行覆盖

> **作为** 测试专项小组成员，**我希望** 执行引擎支持 REST、gRPC、GraphQL、SOAP、MQ 五种协议的用例执行，**以便** 验证路径对全协议范围的适用性。

**验收标准（AC）**：
- AC1：REST 协议：≥5 条用例对真实（或 Mock）服务执行并完成断言判定（P0 部分）
- AC2：gRPC、GraphQL 协议：各 ≥1 条用例执行并完成断言判定
- AC3：SOAP、MQ 协议：各 ≥1 条用例执行并完成断言判定；若环境不可用，降级为"脚本生成成功 + Mock 执行演示"

**优先级**：P1（其中 REST 部分 P0） | **对应 REQ**：REQ-M1AT-009

### Epic 5：报告与缺陷闭环（E-REPORT）

#### US-M1AT-010 测试报告自动生成

> **作为** 测试专项小组成员，**我希望** 执行结束后自动生成测试报告，**以便** 无需人工汇总即可向上游呈现执行结论。

**验收标准（AC）**：
- AC1：报告自动包含：总用例数、通过数、失败数、通过率、失败用例明细
- AC2：从执行结束到报告产出无人工操作
- AC3：报告数值与执行引擎原始输出一致（可程序校验）

**优先级**：P0 | **对应 REQ**：REQ-M1AT-010

#### US-M1AT-011 缺陷清单生成与复测

> **作为** 测试专项小组成员，**我希望** 失败用例自动转化为缺陷清单，并在修复后能对缺陷清单发起复测，**以便** 形成"发现 → 提交 → 复测"的缺陷闭环。

**验收标准（AC）**：
- AC1：每个失败用例转化为一条缺陷记录，含"接口、失败原因、复现步骤"
- AC2：对已修复的缺陷，一条命令发起复测，复测结果更新缺陷状态
- AC3：验收场景中完成至少 1 次完整"缺陷产生 → 复测通过 → 关闭"闭环

**优先级**：P1 | **对应 REQ**：REQ-M1AT-011

#### US-M1AT-012 回归脚本沉淀

> **作为** 测试专项小组成员，**我希望** 复测通过的用例自动沉淀为回归自动化脚本资产，**以便** 后续回归直接复用。

**验收标准（AC）**：
- AC1：复测通过的用例自动进入回归脚本目录，且带有需求/接口溯源信息
- AC2：沉淀后的脚本可被回归执行命令直接重跑，断言结论一致
- AC3：回归目录结构化，并有资产清单

**优先级**：P1 | **对应 REQ**：REQ-M1AT-012

### Epic 6：度量与验收（E-METRIC）

#### US-M1AT-013 自动化率度量方案设计

> **作为** 测试团队负责人，**我希望** 有一份"无人工操作节点数 / 总节点数"的度量方案，**以便** 自动化率有统一、可复现的度量标准。

**验收标准（AC）**：
- AC1：方案文档明确定义 9 个流程节点各自的"人工介入判定标准"
- AC2：给出数据采集方法，在本项目中可实际执行

**优先级**：P1 | **对应 REQ**：REQ-M1AT-013

#### US-M1AT-014 自动化率首次实测

> **作为** 测试团队负责人，**我希望** 在验收演示流程中实测一次自动化率数值，**以便** 获得第一个基线数据支撑项目结论。

**验收标准（AC）**：
- AC1：验收当天全流程跑一遍，记录各节点是否人工介入，产出自动化率具体数值
- AC2：对每个人工介入节点给出瓶颈原因分析

**优先级**：P1 | **对应 REQ**：REQ-M1AT-014

#### US-M1AT-015 验收日交付与彩排

> **作为** 测试团队负责人，**我希望** 验收日有完整彩排过的端到端演示，**以便** 项目结论可信呈现。

**验收标准（AC）**：
- AC1：验收前完成 ≥1 次完整端到端彩排，演示输入锁定
- AC2：每个 P0/P1 卡片的验收场景在验收脚本中有对应环节
- AC3：第 2 天末完成范围检查点：未跑通环节标记降级方案

**优先级**：P0 | **对应 REQ**：REQ-M1AT-015
