# Java 代码统一规范（java-parser）

## 基本原则

- 本服务 Java 基线为 **21（LTS）**，构建使用 **Maven**；依赖锁定于 `pom.xml`，禁止 SNAPSHOT 依赖进入主干。修改前先读取构建文件、相邻实现和测试，不得擅自升级版本、替换框架或引入新依赖。
- 只修改需求涉及的代码，保持向后兼容；REST 契约或序列化字段（对应 `schemas/contracts/` 与接口还原产物 Schema）发生变化时，必须同步 orchestrator 调用方、测试和契约定义。
- 优先编写清晰、可测试的代码，不用过度抽象、反射或复杂设计模式解决简单问题。
- 类头 Javadoc 注明对应规格编号（模块 2 / 3，G3、R2），注释使用中文。
- 禁止提交密钥、令牌、密码、证书或真实个人数据；日志不得输出敏感信息。

## 命名与格式

- 包名全小写；类、接口、枚举使用 `PascalCase`；方法和变量使用 `camelCase`；常量使用 `UPPER_SNAKE_CASE`。
- 名称表达业务含义，避免 `data`、`info`、`temp`、`obj` 等含糊命名；布尔值使用 `is`、`has`、`can`、`should` 等前缀。
- 使用 4 空格缩进、一行一个语句、统一的大括号风格；单行不超过 120 个字符（checkstyle 检查）。
- 禁止通配符导入和无用导入。导入顺序保持「JDK、第三方、项目内部」，各组之间空一行。
- 公共类型和非显然的公共方法应有简洁 Javadoc，说明契约、边界和异常；不要写复述代码的注释。

## 设计与实现

- 解析器基于 JavaParser；对 Dubbo / gRPC / 自定义注解等协议的解析策略按可插拔 `ProtocolResolver` 接口实现，新增协议不改主流程。
- 保持单一职责。REST 接口层只做协议转换与校验，扫描与还原逻辑下沉到解析服务层。
- 依赖通过构造器注入，避免字段注入、全局可变状态和隐藏的服务定位。
- 优先不可变对象和 `final` 局部引用；在语义合适时使用 `record` 定义接口还原产物模型。
- 方法保持短小并尽量只有一个抽象层级；参数过多时使用有明确含义的参数对象，不使用布尔参数控制多个流程分支。
- 时间使用 `java.time`，产物时间戳使用带时区的值并统一 UTC，禁止依赖服务器默认时区。
- `Optional` 主要用于可能缺失的返回值，不用于字段、方法参数或序列化模型；集合返回空集合，不返回 `null`。

## 异常、日志与安全

- 在系统边界校验输入（仓库路径、分支名、扫描范围来自 orchestrator 请求，均须校验）；错误消息应稳定、可理解，但不得泄漏堆栈、SQL、文件路径或安全细节。
- 捕获最具体的异常。禁止空 `catch`、捕获 `Throwable`、无原因地将所有异常包装成通用异常；解析失败的仓库必须显式报告失败原因，禁止静默跳过（对应 R2 风险的诚实呈现）。
- 异常只在能够处理或补充业务上下文的层级捕获；同一异常不要重复记录。保留原始异常作为 `cause`。
- 使用 SLF4J 参数化日志，禁止 `System.out`、字符串拼接日志和敏感数据日志。

## 并发与资源

- 优先无状态服务和不可变数据。共享可变状态必须说明线程安全策略。
- 不直接创建无界线程池；使用项目统一的执行器，并设置队列、超时、取消和关闭策略。多仓库扫描的并发度必须受控可配置。
- 文件、流、连接等资源使用 `try-with-resources`；对 orchestrator 的服务调用必须设置连接和读取超时。

## 测试与交付

- 修复缺陷时先补能复现问题的测试；新增解析逻辑至少覆盖成功、边界（空仓库、语法错误文件、无注解类）和失败路径。
- 使用 Maven Surefire 与项目已有 JUnit、断言和 Mock 方案，测试命名应表达场景与预期结果，避免依赖执行顺序和真实外部服务。解析器核心逻辑覆盖率 ≥70%。
- 优先运行受影响模块的格式检查、静态检查和测试，再按项目要求运行完整测试。
- 完成前检查：无调试输出、无死代码、无未处理警告，异常与日志不含敏感信息，构建和相关测试通过。
