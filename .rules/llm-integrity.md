# LLM 调用与诚实性红线（最高优先级）

本规则为 [docs/09_开发规范说明.md](../docs/09_开发规范说明.md) 第五、六章红线的浓缩子集，适用于所有涉及 LLM 调用与产物生成的代码。**冲突时以 09 文档为准。**

## 一、LLM 调用硬约束

1. **Prompt 版本化**：所有 Prompt 一律存放于 `prompts/` 目录独立文件（含版本号与变更记录），**禁止在代码中内联 Prompt 字符串**。
2. **参数显式**：temperature / top_p / seed 等采样参数显式配置于配置文件，禁止散落硬编码。
3. **输出校验前置**：LLM 输出必须通过 `schemas/` 对应 JSON Schema 校验成功后才能进入下游产物；校验失败按节点失败处理（走断点续跑口径），禁止降级为「截取可用部分」。
4. **调用留痕**：每次 LLM 调用记录输入摘要、输出、耗时、token 数于节点执行日志。
5. **模型唯一**：仅允许调用 GLM-5.3（冻结基线），引入任何其他模型即违反冻结基线，须先走变更控制。

## 二、诚实性铁律

1. **数字不经 LLM**：测试报告、度量报告中的一切数值（通过率、自动化率、接口数、缺陷数）**只能由 execution.json 等结构化产物程序化汇总产生**，禁止由 LLM 生成、改写或「补全」任何数字。
2. **降级必标注**：降级节点按「人工介入」计入（分母固定为 9，不缩减），并在产物中显式记录降级清单，禁止静默跳过。
3. **兜底分列**：兜底演示仓库的结果单独标注，不与真实仓库产物混算，报告分列两组数据。
4. **产物 Schema 版本化**：`schemas/` 下每个产物定义含 `schema_version` 字段，结构变更必须升版本，禁止原地改语义。
5. **产物路径统一**：结构化产物按任务 ID 分目录写入，路径统一由 orchestrator 的 `artifacts` 模块管理，禁止各节点自行拼路径。

## 三、违反后果

上述任一条被违反的代码**不得合入主干**：CI 门禁拦截 + review 必须驳回。涉及裁决口径（D1–D8）的疑问，先查 [docs/06_需求定稿冻结.md](../docs/06_需求定稿冻结.md) 再写代码。
